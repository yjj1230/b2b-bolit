L2 端到端四分支全链路 happy path / 退回拒绝 / 补偿 / Timer 催办 / 幂等重放 / 预订单确认流 / 授权拒绝Temporal TestSuite + 内存 fakeStore/fakeStarter + httptest（纯库）每次合并
L3 系统验证并发守恒、全库对账、覆盖率门禁、图谱 roundtrip、审计链回放、种子数据可重复scripts/（reconcile / audit / concurrency / seeddata）+ make cover每个里程碑

3 · 覆盖率策略

目标值实测（M8，docs/06 §2）说明
domain（FSM/值对象/守恒/幂等）100%100.0%图谱正确性的唯一事实源（硬门禁）
config—100.0%
authz / api / wecom≥98%95.7% / 91.5% / 94.5%余量为防御性错误分支（含网络/限流）
repo / workflows≥98%80.9% / 86.3%余量为 pgx scan error 与每句 SQL 失败返回（触发器级故障注入已覆盖主事务路径）
integration≥98%100.0%含 DemoPolicy 虚拟时长契约（l0_unit 黑盒 + 包内白盒）
全仓合计≥95%（用户）/ ≥98%（文档）87.8%（门禁 85% + domain 100% 硬门禁）差距分析与诚实声明见 docs/06 §2
门禁实现沿用 pilot_app：go test -count=1 -tags integration -coverprofile=coverage.out ./internal/... + awk 数值比较（吸取复盘 R3：字符串比较会误判）；wecom 包因企微 SDK 回调签名/加解密为官方库，覆盖率目标略低于 domain，用集成测试 + 脚本兜底。

诚实声明（沿用 pilot_app 复盘）：错误注入（删表/触发器/类型变更）≠ 真实故障形态（网络抖动/磁盘满/企微限流 45009）；覆盖率 100% ≠ 故障注入等价性 100%。

5 · 测试基础设施

  • L1 前置：make up 起测试 PG（端口 55432）+ 迁移；spicedb serve-testing 需二进制在 PATH（兼容新旧命令名，pilot_app 复盘 R2）。
  • L2 纯库：Temporal TestSuite + fakeStore（业务故障钩子：守恒失败/库存不足/开票失败）+ fakeStarter（模拟 ErrWorkflowAlreadyStarted 竞态）。
  • L3 脚本：concurrency（并发守恒断言四连）、reconcile（四守恒全库聚合）、audit（断链/合法迁移/终态分录）、seeddata（确定性 UUID + runID）。
  • Makefile 目标：test-l0 / test-l1（-tags integration）/ test-l2 / test-l3 / cover / l3-seed / up / down。
  • tests/ 黑盒套件（tests/README.md）：同 L 分层的 HTTP API 视角套件——tests/l0_unit（导出 API 契约：FSM/守恒/幂等/回单分流/接入层默认值）、tests/l1_integration（HTTP × 真 PG：幂等/跨租户/事件链/凭证只追加）、tests/l2_e2e（HTTP 全业务流：款到/非款到/董事长 C-D/部分发货/修改 A-E/拒绝/预订单/凭证/投影；api.LocalRunner 进程内执行真实工作流）、tests/l3_system（HTTP 全链 + seeddata/reconcile/audit/concurrency 脚本驱动）。运行：make test-tests-l0..l3 / make test-tests。与 internal/ 白盒测试互补（白盒在包内保留：覆盖率门禁载体与未导出符号访问）。
  • 错误注入：repo 层（删表/触发器/唯一冲突/关连接池）、workflows 层（fakeStore 故障钩子）、api 层（13 个故障钩子 + 竞态模拟）——支撑覆盖率门禁并证明错误分支行为正确。
