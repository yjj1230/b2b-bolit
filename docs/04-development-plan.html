0 · 前置决策门（Phase 0，里程碑外）

决策项内容退出条件
企微合规（P0）企业认证、自建应用、开通会话存档最小账号集、员工知情同意、外部联系人同意存档可拉取 或 明确降级为半自动（S1 侧边栏 + 人工确认）
业务规则确认客户等级 C/D 判定、合同要素清单、供方分流财务名单、回单 5 天阈值、产品型号对应表维护人、开票入口规则（决策门，见 01 §2.5）（13+1 条待确认规则）形成书面确认清单
演示口径演示叙事（三个记忆点：「客户说一句，订单就有一半了」「回单不卡开票」「仓管看不到价格」）COO 版脚本定稿
决策门输出三分法：可行 / 有条件可行（S2 半自动）/ 不可行。若「有条件可行」，S2 相关里程碑按降级路径执行，其余不变。

3 · 完成定义（DoD，通用）

  1. 该阶段全部 score card 测试绿（含新增回归），零静默 Skip、零假绿、零空测试。
  2. 覆盖率不倒退（M2 起 domain=100%；M8 全仓 ≥98%）。
  3. 文档同步：代码行为偏离图谱/架构 → 先改文档再改代码（roundtrip 纪律）。
  4. 提交历史干净：每阶段一个 commit，可逐里程碑回滚。
  5. 人工闸门纪律：任何自动化路径未过人工确认 Signal，不得生成正式订单/推进关键审批。

4 · 关键路径与风险

关键路径：M0 → M1 → M2 → M3 → M5 → M6 → M8；M4 与 M3 并行、M7 与 M5/M6 并行（依赖：M7 的预订单接线依赖 M5 的 PreOrderWorkflow 契约，先定契约后并行）。

风险影响/概率缓解
企微会话存档合规不通过（员工/外部联系人不同意）高/中Phase 0 决策门先行；降级路径 = S1 侧边栏 + 人工确认（半自动），验收口径改为「有条件可行」
企微 5 天窗口丢消息 / 限流（45009、4000 次/分）高/中原子 checkpoint + 持续拉取 + 重试退避；L1-14 专项测试
LLM 意图识别不确定性（SKU 归一化/多义表达）高/中LLM 只产候选 + 确定性校验 + 人工确认兜底；评测集 ≥50 条、直接确认率 ≥80%、延迟 ≤2 分钟
ReBAC caveat 语法/版本兼容（SpiceDB 升级）中/低spicedb testserver 先行验证（pilot_app 复盘 R2 教训）；固定镜像版本
覆盖率门禁后期补成本高中/高每阶段即时门禁（M2 起），不做期末总攻
审批链复杂导致 Signal/Timer 编排 bug中/中TestSuite 确定性测 Timer/重放（L2-11/13）；子流程隔离
13 条业务规则未确认（回单阈值/供方分流名单等）中/中M0 提交确认清单，未确认项取默认值（5 天/按文档）并在文档标注待确认
