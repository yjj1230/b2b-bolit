3 · 实施中发现的设计偏差（先改文档再改代码）

变更原因是否绑定 CQ
schema.zed caveat 语法校准：expiry_ok(expires_at: timestamp) { expires_at > time.now() } → expiry_ok(expires_at timestamp, now timestamp) { expires_at > now }，now 由判定侧注入SpiceDB v1.33+ 移除冒号类型参数与 CEL time 扩展；文档 §1.4 同步更新CQ-13
PreOrderWorkflow 升级幂等修正：ESCALATED → ESCALATED 自迁移禁止超期 Timer 重复触发时原实现二次升级执行非法自迁移（真库冒烟暴露；生产 48h 后同触发）；修正为仅首次升级迁移状态，重复升级只重新推送CQ-11
本地模式授权判定：LocalRunner 用 StaticChecker 对照表替身本地模式是「HTTP API + 企微 mock 测试模式」；真 SpiceDB 下无关系写入路径（Outbox 投影器阶段二接入），视图/凭证全 403；与 tests/ E2E 同一判定路径CQ-03/13/15
本地模式 Timer 策略：integration.NewDemoPolicy（10s 虚拟时长）内嵌 TestSuite 虚拟时钟自动推进 Timer，催办循环 ~100µs/轮 烧穿 10y 运行预算（~0.4s/闸门）；短时长策略使持续等待约 52 分钟才烧穿预算，交互式演示与慢信号测试可用全 CQ
SHP FSM 增边：SHP_SHIP_ASSIGNING → SHP_SHIPPED（实发完成直连）ship-action 信号在 SHIP_ASSIGNING 闸门直接执行实发（发货+库存扣减单事务）；事件链审计（scripts/audit）暴露中间态 WAREHOUSE_SHIPPING 未经过，FSM 缺直连边CQ-04/07
SHP FSM 增边：SHP_SHIP_ASSIGNING → STK_WAREHOUSE_CONFIRMING（未发货转仓）设计图仅 PARTIAL_SHIPPED 有转仓边；未发货转仓同语义（业务原图 fig12）CQ-06/04
STK FSM 增边：STK_WAREHOUSE_RETURNED → STK_WAREHOUSE_CONFIRMING（退回后重提）状态图缺该回边；实现重入路径时暴露CQ-04
pre_order_events 表补 action 列五域事件表同构（设计遗漏；02 §3.1 字段清单补全）CQ-12
授权对象升级：prestock/shipment/evidence 一等 definition；customer.owner→account_owner；8 细粒度权限；Outbox 投影器rebac_cases_spicedb.html 场景 A–H；人类架构师决策 D1-D4（docs/CHANGELOG-rebac-cases.html §6）CQ-01/02/03/13/15
Shipment/Transfer/ExceptionInvoice 三个子流程以「内联段函数」实现（shpSegment 内发货/退回/转仓分支、invSegment 例外审核分支、stkTransferStep）基线用单 OrderWorkflow 四段编排，状态图语义与设计完全一致；ChildWorkflow 形态留后续迭代CQ-04/05/07/10
orders.state 常量带阶段前缀（ORD_/STK_/SHP_/INV_/PRE_）四分支联合状态跨阶段重名（RETURNED 等），DB 单列状态需无歧义CQ-04
审批任务 ID 随机化（裁决后同 kind 可重建）确定性 ID 使修改 A 类重审无法新建任务（测试暴露的真实缺陷）CQ-05
开票量 = 有效发货量（非整单）部分发货后开票按实发核验（CQ-09 语义落地）CQ-09
