0 · 定位与使用说明

维度说明
读者现场程序员（实施/部署/数据同事），可能不熟悉本仓库
目标让商务（虹励）在受限场景下先把流程走起来：① 飞书侧数据在本系统流里可见可操作；② 企微通道可用（侧边栏/审批卡片/工作台）；③ 原飞书审批流不停
原则① 原流程不打扰（同步只读、绝不回写飞书）；② 受限激活（只同步商务所需子集，不全量迁移）；③ 依赖先行（先映射确认 → 再表来源 → 再同步任务 → 再企微环境 → 最后验收）；④ 现场结论回填（本手册中所有"待现场确认"项，确认后回填本文档形成冻结基线）
本次 vs 下次本次 = 受限场景有限迁移激活（商务走通 + 数据流可见 + 企微发布）。下次全面迁移切换会基于并复用：字段映射表（T1）、表来源清单（T2）、同步 Job 框架（T3）、企微配置基线（T4）——本次工作是一次性资产的沉淀
关联文档v0.1/11-migration.html（同步方案设计）、v0.1/10-deployment.html（部署）、v0.1/06-wecom.html（企微对接）、docs/02-architecture.html §8（迁移布局）、spec/biz/飞书三方审批系统存储表及字段说明.md（飞书字段权威源）
0.1 受限场景定义
用户：仅虹励（销售助理身份）。开放范围：桥接代下单 + 查自己的订单 + 影子新单实时重放（D-012）；商务备货 / 发货 / 开票按 D-013 归 v0.2。财务、仓管继续用飞书原流程。自动下单（会话存档自动拉取 + 意图自动建单）暂缓。锁库存暂不做。

1.3 敏感字段处置规则（02 §8.4 冻结）

字段类别处置验收证据

3.2 同步范围边界（受限场景）

  • 同步子集：仅商务流程所需——订单主档 + 备货/发货/开票当前态与审批状态、事件链、评论；横切表只进归档；
  • 不同步：原始聊天文本（业务库零留存）、Open ID 原文（加密映射）、view_token（丢弃）、密钥（不迁移）、背景任务/回调（归档不重放）；
  • 增量 vs 全量：0.1 数据量小，采用"首跑全量 + 周期增量 + 每日对账"；后续数据量大再切纯增量（11-migration §4）；
  • 冲突处理：本系统侧新产生的操作（商务备货/发货/开票）与飞书侧数据并存——同步只写飞书来源字段，本系统操作字段以本系统为准（字段级来源标注）；
  • 延迟容忍：分钟级可接受（商务看的是当天在途单）；飞书侧新审批状态最长延迟一个周期。
