  • 8 个实战场景（A–H）：A 商务开备货单 / B 改额度·多次发货 / C 仓管确认驳回 / D 客户联系人看物流·上传凭证 / E 跨租户拒绝 / F 作废窗口（阶段二）/ G 临时代办 TTL / H 客户换对接人

  • 6 关系：account_owner / owner(prestock) / warehouse_operator / requester / contact / uploader

4 · 倒推双 graph 验证（阶段 0 核心结论）

4.1 世界知识图谱（01 §1.2）— 本体层面**一致**

  • StockPrepare（备货审批聚合）、Shipment（发货单）已是世界知识图谱的一等实体（01-core-graph.html:65-66）✅
  • 实体语义与 spec 的 prestock/shipment 对齐（备货聚合/一次发货单）
  • 结论：世界知识图谱不需要新增实体，只需补充关系（ASSIGNED_TO/REQUESTS/CONTACT_OF）与 Evidence（凭证）

4.2 授权图谱（schema.zed）— 与本体**不一致**（spec 暴露的裂缝）

  • 本体有 StockPrepare/Shipment，但授权图谱未将其投影为一等 SpiceDB definition——授权维度缺失两个实体级对象
  • 现有把备货/发货权挂在 order 上（order.stock/order.ship），是"聚合视图授权"而非"对象级授权"
  • 判定：这是 graph 内部的层级偏移（实体 vs 授权对象不对齐），spec 的场景 B/C/D 精确隔离要求（prestock:PS-8801#owner、shipment:SHP-02#warehouse_operator）无法由现有 schema 表达

4.3 CQ 覆盖验证

CQ现有 schema 能否精确回答结论
CQ-01 操作权限订单级粗粒度（备货=stock/发货=ship），无法回答"对这张备货单能改额度吗"不精确 → 需 prestock/shipment 级
CQ-02 数据可见范围仓管经 order.warehouse 可见整单；无法表达"客户联系人只见物流视图"不精确 → 需 shipment/customer 级
CQ-03 字段剥离BFF 投影已实现仓管剥离价格✅ 模式一致，需扩展字段清单（客户视图：price/internal_note）
CQ-13 代办时效expiry_ok caveat + order.delegate✅ 模式可复用，需扩展到 prestock/shipment

4.4 代码实测（阶段 0 证据）

  1. schema.zed：仅 tenant/customer/warehouse/order 四个 definition + expiry_ok caveat——与 §2/§3 差距一致
  2. 生产路径从未调用 SpiceDB 关系写入（TouchRelationship/DeleteRelationship 仅存在于 authz 客户端，无生产调用点）——Outbox 投影器是缺失的基础设施，spec 的场景 G/H 与"业务库关系=SpiceDB 关系"承诺均依赖它
  3. api/projection.go 仅按 WAREHOUSE 角色剥离价格——客户联系人视图、仓管"无销售备注"视图未实现
  4. 现有 L1-07 权限矩阵（9 类场景）全部基于 order 级——迁移将影响其断言
