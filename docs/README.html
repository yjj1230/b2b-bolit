📌 项目简介

这是 b2b_pilot_v3 验证项目的设计文档家族（设计先行，实现后回填验证报告）。项目目标（源自 spec/meta.md）：

  1. 业务流落地 + 技术实施的整合验证：以长安仁恒（订单履约型 B2B 企业，全国四仓：阳原 / 长兴 / 东莞 / 成都）为样板客户，落地「线索 → 统一订单 → 三方审批 → 备货 → 发货 → 开票回单 → 回款归档」的订单履约闭环。
  2. Baseline 版本：可运行、可演示、可度量的最小完整闭环，作为后续迭代与其它客户接入的基线。
  3. 演示样板：同一套系统直接向其它客户（如智厨）演示，不为其定制。

项目完整沿用 pilot_app 验证过的「文档驱动 + 图谱 roundtrip 闭环」实践（/Users/laurence/working/projects/pilot_app）：先有世界知识图谱与任务图谱（本文档家族 01），派生架构（02）、测试（03）、开发计划（04）；实现后用 code-review-graph 把代码读回成图，回答能力问题做 roundtrip 验收（05）；执行后复盘（06）。

三大验证支柱（源自 spec/验证项目设计.html）：

支柱验证问题技术选型
🛡 授权SpiceDB 能否承载复杂 B2B 授权（销售只看本人 / 商务全量 / 仓管不见价格 / 代办有效期 / 多租户）SpiceDB RBAC + ReBAC 混合（含 caveat）
🔄 流程Temporal 能否承载四分支主流程 + 三方人工审批 + 子流程 + 催办升级Temporal 主流程 + 子流程 + Signal/Timer
💬 企微「群里一句话 → 预订单 → 人工确认 → 正式订单」是否可行、交互是否顺畅会话内容存档（S2 主路径）+ 应用消息卡片 + 侧边栏 H5（S1）

企微接入因存在多备案切换可能性，独立成文（07-wecom-integration.html），便于灵活管理。

组件用途

范围裁剪（源自 spec/验证项目设计.html §2.2，保持适度）：真实开票/税控、ERP 对接、库存系统对接、BI、化百道线索、多仓批号精细库存均不在本 baseline 验证范围，留后续阶段；库存以「仓库 × 产品 × 数量」粒度做数量守恒校验。
