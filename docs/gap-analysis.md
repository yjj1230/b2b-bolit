## 3 · 双 Graph 新定义与现有 01-core-graph 的映射

用户要求 0.1 双 graph 是「**业务知识图谱 + 业务流程操作图谱**」，且要看到：
- 0.1 需求的业务知识（比产品层面更细：具体业务操作、业务行为、业务交互）

映射关系：

| v0.1 双 graph | 现有 01-core-graph 素材 | 重构策略 |
|--------------|------------------------|---------|
| ① 业务知识图谱（世界图） | §1 世界知识图谱：15 CQ + ontology + ER + SpiceDB + 事件图谱 | 保留 CQ/本体/ER/授权/事件骨架，但**实体与关系按 demo 现实校准**：新增「发票关联（多单合并开票）」「凭证机器人」「仓库群」「守门员确认」等 0.1 业务对象；仓库实体标注真实外租仓 |
| ② 业务流程操作图谱（任务图） | §2 任务图谱：主流程 + 四流程状态机 + 预订单 | 重构为**按 7 角色 17 场景展开的操作图谱**：每个场景 = 入口 → 操作 → 状态转移 → 角色交互；保留 FSM 作为底层状态基座，操作层覆盖 demo 全部动作（选仓/收货地址/守门员/发给客户/多单合并开票/仓库群回单/终审） |
| 分离边界 | 现有文档知识图与任务图边界 | 知识图谱回答「业务上有什么」（实体/关系/规则/权限）；操作图谱回答「业务怎么发生」（场景/动作/转移/交互）。操作图谱以 demo 场景为纲，知识图谱以 CQ 为纲 |

## 4 · 11 章节差距分析

### 01-business-graphs.html（业务知识图谱 + 业务流程操作图谱）【新增主文档】
- 现有素材：01-core-graph.html 全文（§1 世界图 + §2 任务图 + §3 维护规则）
- 与 demo 差距：①现有 ER 无「发票↔订单多对多关联」（A4）；②无守门员确认对象（A3）；③凭证链只有 evidence_versions 无「机器人抓取」路径（A6）；④仓库为四仓 vs demo 华南仓/外租仓；⑤任务图是 FSM 视角而非角色操作视角（用户要"比产品层面更细的具体业务操作"）
- 重构策略：双图分节；知识图谱用 ER + CQ 表 + 规则表；操作图谱按 7 角色 × 17 场景组织，每场景给 mermaid 操作流；保留 SpiceDB 授权与事件图谱作为知识图谱子节
