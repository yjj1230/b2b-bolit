设计文档审查
对齐三方存储 schema 后的剩余风险

本记录复核 docs/ 当前 Markdown 与发布版 HTML，并以 spec/meta.md、spec/biz/飞书三方审批系统存储表及字段说明.md、两个表头 Excel 及历史 review 为依据。上一轮意见已先落到设计文档；以下只列仍需业务决策或实施证据关闭的问题。

3条剩余发现
2 × P1实现或验收阻断项
静态审查未执行 Go/PG/SpiceDB/企微运行测试

01 · 审查结论

文档结构已基本具备实施基线条件，但还不能宣称业务规则和运行证据已经闭环。 本轮已将 STK 备货、分域事件、租户复合 FK、迁移阶段映射、INV 七节点、仓管只读投影和 A/B/C/D/E Score Card 写入设计；剩余风险集中在开票入口决策、可执行授权验证，以及敏感迁移资料的证据治理。

02 · 剩余发现

P1 开票入口规则仍未取得业务确认

当前设计采用“合同完成即可申请，实际开票时按有效发货的数量与金额核验”的折中方案；状态图已经允许从 READY_FOR_INVOICE 进入申请，但文档仍明确标注来源规格与早期“未发货不可开票”冲突，ADR 也把它列为待业务确认。原三方 schema 只证明存在 available_invoice_amount 与 available_invoice_qty，并不能单独证明申请入口规则。

依据：01-core-graph.md:545-555、01-core-graph.md:562-563、02-architecture.md:240-245；源字段见 schema 说明:408-409。

建议：由业务方书面选择“可先申请”或“必须先有部分/全部发货”，并将选择同步到 INV 状态入口、L0-04/L2-10、L3-02 对账规则和验收脚本。不能以当前折中默认值代替决策门。

P1 授权与复合 FK 仍缺少可执行验证

文档现在给出了 SpiceDB 版本假设、warehouse->staff 只读路径、BFF 价格字段投影，以及“所有 FK 必须包含 tenant_id”的约束，但仓库中仍没有实际的 schema.zed、PostgreSQL migration 或 L1 集成测试可供编译和运行。仅凭设计文本无法确认箭头语法、关系类型、复合 FK 和仓管投影在同一实现中成立。

依据：01-core-graph.md:251-359、02-architecture.md:143-172、03-testing.md:51-64；M1/M4 门禁见 04-development-plan.md:31-37。

建议：M1 先提交真实 schema.zed 和迁移 SQL，固定 SpiceDB 镜像并执行 schema compile；L1 至少证明“本仓可读但无价格、跨仓拒绝、跨租户拒绝、同键不同租户互不冲突”，失败即阻断后续流程实现。

P2 横切归档与敏感字段的迁移治理还不够可验收

本轮已经把 external_instances、后台任务、回调、多维表映射、机器人消息和仓库通知明确为 legacy_* 只读归档，并保留四阶段实例/任务映射。但源 JSONL 仍含 Open ID、访问令牌、文件路径、请求/响应体、审批表单和评论正文；当前迁移章节尚未给每类字段定义脱敏规则、加密边界、TTL、访问角色和迁移后删除证明。

依据：源系统说明中的横切表字段 schema 说明:459-627 及敏感字段注意事项 schema 说明:629-634；目标归档策略见 02-architecture.md:272-287。

建议：在迁移前增加字段级 mapping/retention 清单和验收证据：哪些字段进入 PG、哪些只进加密对象存储、谁可访问、保存多久、迁移后如何验证业务库无令牌/原始响应残留。归档数据不得重新触发旧任务或发送旧消息。

03 · 本轮已完成的文档修正

区域已落地修正
领域与数据库新增独立 stock_prepares/stock_prepare_items 与 STK 事件；SHP 通过 stock_prepare_id 连接，保留分批、出库和回退语义。
事件与审批ORD/STK/SHP/INV/PreOrder 五类事件分域 append-only；approval_tasks 增加 stage、源 task ID 和 INV 七节点类型。
租户与迁移明确复合 FK；正式表清单纳入 approval_comments、legacy_flow_mapping、migration_batches；映射覆盖 flow/stage/instance/task 与 resubmit revision。
验收与发布版Score Card 的 L2-02 覆盖 A/B/C/D/E；roundtrip、Workflow ID、仓管投影、开票双维守恒和 HTML 安全表已同步 Markdown。

04 · 审查边界与解除顺序

  1. 先完成开票入口书面决策，并更新 INV 状态图及对应测试断言。
  2. 提交并编译真实 SpiceDB schema、复合 FK migrations，跑通 L1 权限与租户隔离矩阵。
  3. 冻结迁移字段级 mapping/retention 清单，再以 JSONL fixture 做快照、事件、守恒和敏感字段残留对账。
  4. 最后按 07 §8.2 记录 W3/W4 真实企微环境证据；Fake 全绿不能替代真实验收。

审查方式：静态交叉核对文档、源 schema 字段和 HTML 结构；本记录生成时未执行应用测试，也未将新增 spec/ 参考资料纳入 Git。
