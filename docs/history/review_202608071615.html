3 · 挑战：A3 真实运行环境（本轮新增证据）

理论 A3 维度要求「真实或等价运行环境」。项目此前的全链证据全部来自 LocalRunner（TestSuite 虚拟时钟 + StaticChecker 替身）——真实 Temporal 编排 + 真实 SpiceDB 授权从未被运行验证过，这是最大的证据空白。本轮补齐：

真实运行验证操作结果
真实 Temporal 全链（款到）cmd/worker（TaskQueue b2b-order）+ cmd/api（mode=temporal）→ 创建订单 + 6 信号✅ 状态 INV_CLOSED，事件链 27 条（tail: PAYMENT_TRACKING → CONTRACT_ARCHIVED → CLOSED）
真实 Temporal 预订单全链创建预订单（PRE_CAPTURED）→ preorder-confirm 信号✅ PRE_ORDER_REQUESTED + 派生正式订单 1 条（order:chang-an:pre:*）
真实 SpiceDB 授权判定seedrel 预置关系后：u-supervisor 查订单视图 / u-contact 越权✅ 有权 → INV_CLOSED 视图（amount 100000）；越权 → permission denied（与 StaticChecker 结论一致）
真实模式待办GET /api/v1/todos（u-wh-yangyuan）✅ 返回审批任务（AT-*）
事件数差异观察真实 Temporal 27 条 vs LocalRunner E2E 断言 ≥26✅ 27 ≥ 26，无回归；差异来源：真实运行无 TestSuite 的虚拟时钟压缩，预置/重试路径事件数略多（非正确性问题）

挑战发现（本轮 A3 暴露的 4 个盲区，全部修复/工具化）：

  1. 真实模式授权关系无初始化路径（投影器阶段二未接线 → order#view 全拒绝）→ 新增 scripts/seedrel（幂等；-schema 首启建 schema、-orders 补订单层级边 owner/customer/tenant）。
  2. SpiceDB 预共享密钥配置陷阱：cmd/api 默认 b2b-dev-key，容器实际 pilot-dev-key → 所有授权预检静默失败为 permission denied（错误 token 不报连接错误）→ 部署时必须显式配 B2B_SPICEDB_KEY（已写入 07 §10 与 seedrel 用法）。
  3. SpiceDB 持久化库需手动 migrate：serve 未自动迁移（relation_tuple_transaction 不存在）→ 开发环境重置流程：dropdb/createdb → spicedb migrate head → 重启 → seedrel。
  4. authz.Relationship.SubjectType 默认值陷阱：留空时 SpiceDB 校验失败（首个外部调用方 seedrel 暴露）→ relToUpdate 默认 user（schema.zed 全部 subject 均为 user）。
