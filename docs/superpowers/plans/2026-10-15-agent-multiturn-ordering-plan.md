# Agent 多轮下单实现计划

## 目标

按照 `docs/superpowers/specs/2026-10-15-agent-multiturn-ordering-design.md`，把多轮消息归并到同一个订单会话和主预订单，并保证逐消息版本化、字段冲突可恢复、消息幂等和旧卡片可识别。

## 实施顺序

1. **确定性合并器**
   - 新增 `internal/agentorder/merger.go`。
   - 以纯函数形式合并累积快照与本轮字段补丁。
   - 明确区分用户明确覆盖、人工修改、模型推断和无明确替换语义的冲突。
   - 先添加表驱动单元测试，覆盖补充、明确覆盖、冲突、人工优先、缺失字段和无副作用。

2. **领域状态与版本模型**
   - 增加 `PRE_COLLECTING`、`PRE_EXPIRED`、`MANUAL_REQUIRED` 等状态。
   - 扩展预订单草稿模型，保留累积快照、本轮 patch、差异和冲突状态。
   - 保持现有确认版本校验兼容。

3. **消息事实与会话持久化**
   - 新增 migration 010：`inbound_messages`、`order_conversations`、草稿来源关联表。
   - 为 `pre_orders` 增加会话关联和确认版本字段。
   - 增加租户边界、唯一键和并发锁所需索引。

4. **会话归并服务**
   - 新增消息落库、会话选择和会话级合并接口。
   - 同一会话使用数据库行锁串行处理。
   - 重复消息直接返回已处理结果；歧义和冲突不推进 CURRENT 版本。

5. **入口接线**
   - 修改默认 mock 入站和 deferred 存档入口，先落消息再归并。
   - 后续消息复用同一个主预订单，不再为每个 msg_id 创建独立预订单。
   - 保留现有人工确认与审批工作流边界。

6. **验证**
   - 运行合并器、仓储、工作流和入口测试。
   - 再运行 `go test ./...`；任何失败都按测试结果修复后再报告。

## 不在本次实现中改变

- LLM 仍只负责意图理解和字段候选提取。
- 客户、SKU、价格、权限、合同、库存和正式订单审批仍由确定性后端和人工确认负责。
- 不修改正式 OrderWorkflow 的审批和履约状态机。
