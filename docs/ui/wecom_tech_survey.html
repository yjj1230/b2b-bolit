PART A · 沟通通道矩阵 —— 客户 ↔ 销售实际工具 × 企微触达能力

以客户与销售之间实际使用的沟通工具组合为全局视角，共 4 类通道（C1-C4）。核心结论：只要会话中有企微参与（销售侧用企微客户端），订单助手即可触达；纯个微↔个微（双方均无企微参与）企微应用无法触达，需引导客户进入企微体系。本系统 spec 的主战场（「广西天华 · 供应协同群」= 企微成员 + 个微客户的外部客户群）落在 C2。

通道客户侧工具销售侧工具典型会话侧边栏应用（S1）工具栏入口 / 全屏 H5消息卡片推送（S3）身份识别与群解析群上下文（chatId）限制与降级

可触达		 个微（微信用户） 企微（外部联系人单聊） 销售 ↔ 客户 1 对 1 私聊（微信好友形态） ✅ 外部联系人单聊可见（entry=single_chat_tools，3.0.24+） ✅ 移动端工具栏入口 + 全屏 H5 ✅ 客户联系 API 可向 external_userid 发送应用消息卡片 ✅ ww.getCurExternalContact（path/100746）→ external_userid；unionid 关联（path/95900） —（单聊无群 ID，走客户维度） 需客户联系权限；仅「客户」（非「其他外部联系人」）可管理；侧边栏仅外部会话可见

C3
可触达		 企微（他企业成员） 企微（外部联系人 1 对 1 / 上下游） 企业间单聊（普通外部企微用户 / 上下游企业成员） ✅ 外部企微联系人单聊可见（single_chat_tools）；上下游体系用上下游聊天工具栏（path/95709） ✅ 工具栏 + 全屏 H5 ✅ 应用消息卡片（客户联系/上下游范围内） ✅ 普通：getCurExternalContact；上下游：获取上下游联系人 ID（path/100367）→ open_userid + corpId —（单聊） 上下游需企业互联/上下游关系；互联群功能需开启
C4
可触达		 企微（多企业成员） 企微（上下游/企业互联群） 上下游协作群：多企业企微成员同群（互联群） ✅ 上下游聊天工具栏（path/95709）+ 获取上下游互联群 ID（path/100368） ✅ 工具栏 + 全屏 H5 ✅ 应用消息卡片（互联群会话） ✅ 上下游互联群 ID → 群详情 → 各企业成员（corpId + open_userid）；ww.createCorpGroupChat 可建互联群（path/94430，需开启互联群功能） ✅ 互联群上下文 需开启互联群功能；仅局校互联和上下游企业可调用；含外部联系人时群上限 40 人
C0
不可触达		 个微 个微（纯微信，无企微参与） 销售未用企微：微信 1 对 1 / 微信群 ❌ 无企微客户端，侧边栏不存在 ❌ 无法挂载 ❌ 无法推送 ❌ 无企微身份体系 ❌ 降级路径：引导客户添加企微/进入客户群（「联系我」插件 path/93071、群活码），或改用微信小程序/公众号方案（非本系统范围）

D1

身份鉴权与可见范围

运行系统进入 H5 的统一鉴权链（官方能力，07 §6.1 设计一致）：

H5 启动 → GET /api/v1/wecom/jsapi-config（服务端算 ww.register 企业签名 + ww.agentConfig 应用签名，双票据） → ww.config + ww.agentConfig（前端注入） → OAuth2 静默授权（scope=snsapi_base，无感知跳转） → code → POST /api/v1/auth/exchange → 服务端换 userid + 签发会话 → 后续请求携带 X-WeCom-Context（服务端重认证身份与上下文，不信任前端传入身份）

企业微信 vs 个人微信（选型对照）

维度企业微信个人微信对 B2B 履约的意义
