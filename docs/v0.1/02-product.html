业务场景体系

本文档是双 Graph（01-business-graphs.html）的承接者：业务知识在场景里有着落点，业务操作被整合为一个个业务场景。一个场景 = 用一条业务流程串起多个动作，完成一个单一业务使命。所有场景与操作以 ord_fulfill demo 为裁决源——demo 已集成运营、产品、客户直接反馈，与之冲突的文档一律以 demo 为准。

⚠️ 口径提示（D-013）：A1-A8 产品变更是 demo 全量设计资产；v0.1 只开放销售助理桥接闭环；商务 / 财务 / 仓管履约在 v0.2，销售 / 主管 / 董事长在 v0.3。见 版本规划.html。

2 · 场景分组详解（五大业务使命）

2.1 使命一 · 客户沟通与查单

XS1 · 查订单/订单详情

业务使命：客户在群里口头问单/催进度，销售快速定位订单、核对进度，并把订单信息一键发给客户。

  • AI 识别问单意图直达订单详情（履约时间线 · 物流/预计送达）；详情页可返回客户订单首页（汇总 + 状态筛选），人工翻看/筛选/查找；
  • 「发给客户」一键发送客户可见订单卡片——第一轮守门员：点「发给客户」后须销售再点一次确认，确认后卡片才发群；先收紧后放行；
  • 订单未发货时客户可见卡片仅「已下单 + 预计到货」不含金额。
XS5 · 查物流（图片发群）

业务使命：客户催物流时，销售把物流信息以图片形式发到群里（图片比文字更直观、更可转发）。

  • 订单明细直接展示订单进展与物流信息（物流公司/单号/当前进度/预计送达）；
  • 「生成物流图片发群」→ 守门员确认 → 物流图片发群。

2.2 使命二 · 下单（四种下单方式并存）

方式场景适用关键设计
人工下单XS2客户提的新需求不适合智能下单时单页长表单（客户顶部锁定不设分步）；字段按「客户与归属 / 结算信息 / 合同与附件 / 商品明细 / 补充说明」排列；单价自动带出最近订单（协议价上限内可改）；合同按主体自动匹配模板 HT-2025-0038；风控额度校验；提交后销售主动发群通知（自动化降级做，避免 surprise）
智能下单确认XS3群内消息适合自动提取要素时AI 提取要素 → DRAFT 汇总卡（引用原话/主体/产品/数量/单价/包装/账期/付款方式/交期/特殊标记）→ 销售是唯一可确认角色 → 确认一次即正式订单（幂等防重复）；待办+私信双通道提醒；近 30 天质量反馈提示不阻断下单
工作台代下单XSZL1销售助理从工作台入口代销售下单先选「下单归属销售」（决定可选客户范围）→ 客户自动补全 → 表单与销售下单一致

订单创建现状（A7 多方分担）：陈虹励（佘总订单 + 董事长订单，约 20%）+ 销售助理 1（张磊的订单）+ 销售助理 2（合约的订单）+ 销售本人（其余全部订单）。四种下单方式覆盖全部创建主体。

2.3 使命三 · 履约推进（审价 → 终审 → 备货 → 发货）

选仓+收货地址"] B -->|"C/D 级"| C["董事长终审 DSZ1"] C -->|"通过"| D C -->|"驳回"| X["已驳回 (终态)"] D -->|"通过"| E["仓管确认接受 CG1"] E -->|"确认"| F["仓管确认发货 CG2

  • 审价即审批（XSZG1）：审价卡直接展示公司/账期/产品/数量/单价/到货地址，无需从金额反推；B 级订单无董事长终审；审批历史可追溯；
  • 备货（SW1）：待办按功能分门别类（备货/发货/开票三入口，审价属销售主管）；备货详情含收货地址，底部「选备货仓 / 写备注 / 通过 / 驳回」——根据收货地址选仓（A1）；备货通过后发起备货单 → 生成发货单给仓管；锁库存暂不做；
  • 仓管两步确认：确认接受（任务要素无金额）→ 确认已经发货（填写实际数量，守恒校验拦截超发）；
  • 商务工作台（SW3）：全租户待办按闸门类型标注，直达同一套操作卡片。

2.4 使命四 · 单据与凭证（开票闭环）

  • 凭证上传主路径反转（A2）：财务改在订单后台页面上传电子凭证（PDF/图片）——财务每天对电脑，最稳路径；AI 自动识别（发票号/开票金额/税额）并匹配订单；校验开票金额 = 已发货金额（不超发货）；凭证只追加不覆盖（v1→v2）；
  • 多单合并开票（A4）：发票与订单分离，通过「关联」连接——一笔款可跨多笔订单；关联可追加（先关联 1、2 笔，漏了可补第 3 笔）；收款金额/发货金额/开票金额三金额分别展示；未开票额度保留在订单上，由财务确认关联到哪张订单继续开；
  • 无回单开票（CW2）：无签收回单超期 → 开票申请流转至财务待办（例外审核）；财务驳回/放行；规则待确认（A5：找宋主任/财务负责人/张总确认 + 整理「现状-问题-建议」文档 + 算资金延后 30 天利息账）；
  • 仓库群回单（CG3）：两个外租仓库仓管把签收回单统一发企微仓库群 → 凭证机器人自动抓取/OCR 识别/匹配订单/登记归档（只追加）；虹励需先补仓库群现状截图并升级企微群；手动上传 Tab 保留备选；
  • 凭证机器人降级兜底：只服务没有电脑操作场景的人（如餐馆类客户、在外跑的销售）；销售合同回传仍走机器人。

2.5 使命五 · 全局视图

  • 销售工作台（XS4）：订单并行 40–50 笔时无需逐个进群，聚合本人全部待办（无群上下文）：智能下单确认（超时置顶）、审价驳回·待补充（AI 解析驳回意见展开建议修改字段）、订单评论提醒、回单异常；
  • 商务全量（SW2）：独立打开订单助手，服务端按 ops 聚合投影租户全量订单（时间倒序）；商务可见价格/账期/内部备注（全字段），与销售仅本人订单不同；每笔展示四节点状态；可向下承接备货处理。

5 · 产品原则

  • 人工确认是终点：任何 AI 生成结果（智能下单、凭证识别、发群内容）都以显式人工确认为终点，确认前不产生正式业务结果；
  • 先收紧后放行：守门员第一轮全部强制，逐步释放自动化；
  • 降级不吓人：群通知由销售主动发送（自动化降级做），凭证机器人兜底无电脑场景——自动化替代不制造 surprise；
  • 字段投影即呈现：仓管看不到价格、客户看不到金额/内部备注——UI 表现为字段级显隐而非整页拒绝；
  • 预填最大化：下单表单按群上下文/客户档案/最近订单/框架合同最大化预填，减少填写（「客户说一句，订单就有一半了」）；
  • 只追加不覆盖：凭证（发票/回单）版本只追加，任何版本可回放；
  • 金额守恒可对账：发货 ≤ 备货 ≤ 订单、开票 ≤ 有效发货、三金额分展——每笔订单的业财关系可核可算。
