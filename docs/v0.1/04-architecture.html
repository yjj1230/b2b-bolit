0.1 数据流要点
① 飞书侧（数据库/多维表/三方审批流）是既有事实源，原审批流不停；② cmd/sync 周期性把飞书数据单向只读同步进本系统 PG（映射为订单/审批/回单视图），商务在本系统流里可见可操作；③ 本系统的写操作（商务侧流程）不会反向写回飞书——0.1 是「平行流」，不是「替换流」；④ 凭证机器人从仓库群抓取回单后登记进本系统，回单状态由最新凭证版本推导。

wecom → apiHTTP（转接层）企微回调 → HTTP 动作转接（EventKey → 信号/查询），企微不承载业务逻辑

4 · 关键机制沿用（0.1 适用范围）

4.1 Temporal 编排

机制用法0.1 适用范围
主流程 OrderWorkflow四段强顺序推进（ORD→STK→SHP→INV），段内状态机表驱动全量启用（0.1 全部订单走此链）
人工闸门 Signal审价/终审/备货/发货/开票/例外审核全部 Signal 等待；AI 路径不得绕过全量启用（含守门员确认）
Timer 催办24h 提醒 / 48h 升级；无回单 5 天例外；预订单 24h 升级启用（参数经接入层策略读取）
子流程 ShipmentWorkflow一次发货（分配→实发→库存联动单事务）；一张发货单只发一次启用
子流程 TransferWorkflow转仓/退回（回 STK 段）保留，0.1 可用性待确认（demo 未演示转仓）
子流程 ExceptionInvoiceWorkflow无回单超期/提前申请 → 例外审核启用（CW2 无回单开票）
PreOrderWorkflow智能下单：消息 → 预订单 → 销售确认 Signal → 派生正式订单启用人工段（智能下单确认卡）；自动捕捉段暂缓

4.2 SpiceDB 授权

  • 唯一授权判定点：authz.Checker → CheckPermission（FullyConsistent，撤销即时生效）；应用代码零硬编码授权；
  • 三层模型：租户隔离 ∩ 资源级关系（prestock/shipment/evidence 一等对象）∩ caveat（expiry_ok 代办时效）；
  • 字段级投影（BFF）：仓管剥价（CQ-03）、客户联系人剥金额/内部备注——demo 中「金额对仓管不可见」即此机制；
  • 0.1 角色矩阵：销售（本人）/商务（ops 全量）/销售主管（审价闸门）/财务（到账+开票+例外）/仓管（本仓剥价）/董事长（C/D 终审）/销售助理（代办语义）。

4.3 一致性防线（7 层 · 0.1 启用标注）

#防线防什么0.1 状态
1CHECK 约束负库存/负数量/超量发货（qty>=0、quantity>0、shipped_qty<=planned_qty）启用（CG2 超发拦截）
2行锁 FOR UPDATE并发发货超卖、并发确认竞态启用（库存扣减侧见 #4 标注）
3UNIQUE(tenant_id, idempotency_key)重复下单/发货/开票/建预订单启用（XS3 确认只发生一次）
4单事务多写发货+库存扣减；开票+守恒校验；状态+事件链启用（0.1 库存扣减暂缓，守恒与事件链保留）
5守恒聚合校验∑发货≤订单、∑开票≤∑发货、库存≥0（对账根基）启用（L3 脚本）
6FSM 表驱动非法状态迁移启用
7补偿/回退路径退回重提、转仓换仓、开票失败重试启用（驳回/重提在 demo XS4）

4.4 幂等机制（三层叠加）

层机制0.1 落点
1API/DB：(tenant_id, idempotency_key) 复合唯一 + payload_hash 指纹下单/发货/开票幂等；同键异 payload → 409
2Temporal：WorkflowID = "order-" + tenant + "-" + key；重复 Start → 回查同一流程智能下单确认派生订单
3业务域消息幂等：(tenant_id, group_id, msg_id) 唯一；分录级幂等（:ship/:inv 段后缀）企微重发/重放防重复建单

7 · ADR 摘要（0.1 决策）

决策选择理由
