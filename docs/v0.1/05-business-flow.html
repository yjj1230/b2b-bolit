业务流程 · 0.1
已核对的全流程

本文档对应已经核对好的业务流程：下单（人工 / 智能确认 / 代下）→ 审价 → 董事长终审（C/D）→ 备货（选仓）→ 发货（仓管两步）→ 开票（凭证 + 合并开票）→ 回单（仓库群）。每个节点给出角色、操作、状态转移、守恒校验与异常处理；0.1 特殊处理（发群守门员 / 多单合并开票 / 无回单开票规则待确认 / 仓库群回单）逐点标注。

2 · 节点详述

N1 · 下单（三种方式并存）
维度内容
角色销售（XS2/XS3）、销售助理（XSZL1 工作台 / XSZL2 客户群入口）、商务虹励（佘总+董事长订单 ~20%，A7 多方分担）
操作人工：单页长表单（客户/归属锁定、结算信息、合同自动匹配、商品明细、补充说明）→ 提交；智能：AI 提取要素 → DRAFT 卡 → 销售确认（一次成单）；代下：选归属销售（工作台）或群上下文自动带出锁定（群入口）→ 表单预填 → 提交
状态转移→ 已开单（四节点第一个节点；幂等键防重复，确认只发生一次）
守恒校验风控额度校验（额度使用 76% 在额度内）；幂等防重复（order.submit idempotency_key）
异常处理重复提交 409 幂等回执；表单校验失败提示（数量超上限/无权为客户下单）；智能下单低置信 → 轻提醒不自动建单（0.1 暂缓段）
N2 · 审价审批（销售主管）
维度内容
角色销售主管（XSZG1；审批即审价）
操作审价卡直接展示公司/账期/产品/数量/单价/到货地址（无需从金额反推）→ 详情核对 → 通过/驳回；「历史」Tab 可追溯
状态转移待审价 → 待备货（A/B 级）或 待终审（C/D 级）→ 已驳回（终态，可重提）
守恒校验单价在协议价上限内（预填带出最近订单单价，可改但受限）
异常处理驳回 → 销售收到「审价驳回·待补充」（XS4：AI 解析驳回意见展开建议修改字段，修改后重新提交）；审批超时 Timer 催办（24h 提醒/48h 升级）
N3 · 董事长终审（C/D 级）
维度内容
角色董事长（DSZ1；仅 C/D 级客户订单进入此闸门）
操作订单详情：金额/客户等级/审价结论（主管已通过）/账期（全字段）→ 通过/驳回
状态转移待终审 → 待备货（通过）/ 已驳回（终态 + 出站「被驳回」卡片）
守恒校验客户等级 C/D 判定（A/B 级无此闸门）
异常处理驳回即终态；终审通过后才进入商务审核/备货链
N4 · 商务备货（0.1 主角节点）
维度内容
角色商务（SW1/SW2/SW3）
操作待办按功能分门别类（备货/发货/开票三入口）→ 备货详情（产品/数量/交期/收货地址）→ 底部四按钮：选备货仓（根据收货地址选仓）/ 写备注 / 通过 / 驳回
状态转移待备货 → 已备货（备货通过 → 发起备货单 → 生成发货单给仓管）；驳回 → 通知销售
守恒校验备货守恒：∑备货确认量 ≤ 订单数量（CQ-06）；锁库存暂不做（A1）
异常处理仓管评估能否备货，可转仓或退回（转仓流程保留待确认，M5）；备货超 24h 优先处理；驳回支持备注
N5 · 仓管发货（两步确认）
维度内容
角色仓管（CG1 确认接受 / CG2 确认已经发货；金额对仓管不可见）
操作① 发货要求推送本仓待办 → 任务要素核对（产品/数量/目标仓/交期，无金额）→ 确认接受；② 物流取走货后 → 填本次发货数量（应发 5 吨 · 已发 0 吨）→ 确认发货
状态转移待发货 → 已接受 → 已发货（shipped_qty 累计；全部发货 ⇔ 累计 = 订单量）
守恒校验超发拦截（CQ-07）：输入 6 超出应发 5 → 拒绝；修正 5 → 通过；CHECK(shipped_qty <= planned_qty) + 行锁
异常处理少发 → 回退备货层（按原分批计划继续）；仓管退回/转仓申请；发货后进入回单环节
N6 · 财务开票（凭证 + 合并开票）
维度内容
角色财务（CW1 上传凭证 / CW2 无回单开票例外审核）
操作主路径：订单后台 → 订单详情页上传电子凭证（PDF/图片）→ AI 识别（发票号/金额/税额）匹配订单 → 校验 → 登记（凭证追加 v2）；多单合并开票：发票-订单分离通过「关联」连接（可追加）→ 三金额分展（收款/发货/开票）→ 未开票额度保留在订单上由财务确认关联到哪张订单继续开；兜底：凭证机器人（无电脑场景）；销售合同回传仍走机器人
状态转移待开票 → 已开票（INVOICING → INVOICED）；无回单 → 例外审核（CW2）
守恒校验开票守恒（CQ-09）：开票金额 = 已发货金额（不超发货，金额+数量双维度）；回单不卡开票
异常处理开票失败可重试；无回单开票规则待确认（A5）：找宋主任/财务负责人/张总确认 + 整理「现状-问题-建议」文档（资金延后 30 天利息账）；例外拒绝 → 待补回单
N7 · 回单（仓库群 → 凭证机器人）
维度内容
角色仓管（CG3；两个外租仓库）
操作仓管把签收回单统一发在群聊里 → 仓库群升级为企微群 → 凭证机器人自动抓取 → OCR 识别签收信息 → 匹配订单 → 登记归档（凭证 v3 只追加）；「上传凭证」Tab 手动备选
状态转移回单登记 → 回单环节闭合（回单状态由最新凭证版本推导，杜绝篡改为已回）
守恒校验凭证只追加不覆盖（CQ-15）；版本单调递增
异常处理虹励需先补仓库群现状截图并升级企微群（P2）；升级前走手动上传备选；识别失败 → 人工补登
N8 · 发群通知（守门员横切）
维度内容
角色销售（唯一确认角色）
操作任何内容发客户群（订单卡片 XS1 / 物流图片 XS5 / 发票 CW1）→ 点「发给客户」→ 守门员再确认 → 发送；确认记录 append-only 审计
状态转移待确认 → 已确认（发送）/ 取消（保留在详情页）
守恒校验幂等：确认只发生一次；客户可见卡片字段投影（未发货订单不含金额）
异常处理先收紧后放行：0.1 全部强制；「哪些内容可直发、哪些必须审核」规则表 P5 待确认

3 · 0.1 特殊处理清单

#特殊处理流程落点状态
S1发群守门员：任何内容发客户群前销售确认N8 横切（XS1/XS5/CW1）第一轮强制（A3）
S2多单合并开票：发票-订单分离、关联可追加、三金额分展、未开票额度保留在订单上N6（CW1）启用（A4；业财归属 P4 待确认）
S3无回单开票规则：例外审核流程已跑通，规则本身待确认N6 异常（CW2）待确认（A5）
S4仓库群回单：仓库群 → 企微群 → 凭证机器人抓取N7（CG3）启用（A6；群升级 P2 前置）
S5凭证上传主路径反转：订单后台为主，机器人兜底，销售合同回传仍走机器人N6（CW1）启用（A2）
S6订单创建多方分担：四类创建主体 + 群入口归属自动带出锁定N1（A7）启用
S7选备货仓 + 收货地址：根据地址选仓；锁库存暂不做N4（SW1）启用（A1）
S8飞书数据同步：原审批流不停，同步进本系统可见可操作全流程输入侧启用（A8；见 11-migration）
