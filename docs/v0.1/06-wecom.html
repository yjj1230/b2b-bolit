3 · 回调接口

回调URL / 触发验证路由到0.1 状态
消息回调（企微 → 本系统）https://<备案域名>/wecom/callback/<tenant_id>URL 验证（GET 解密 echostr 1 秒内响应）；POST body {"encrypt":...} + query 签名VerifyCallback 验签 → CallbackHandler 解析 EventKey → HTTP API 动作（信号/查询）启用
审批回调（卡片按钮）template_card 按钮（EventKey：approve:<taskID> / reject:<taskID> / preorder:confirm|ignore|modify / chairman-review / payment-confirm / receipt-ex-review / invoice-issued）回调验签 + 按钮 key 上下文→ POST /api/v1/orders/{id}/signal/{signal} 或预订单信号（幂等回执）启用（W5 已验证）
OAuth 回调（S1 H5）网页授权 snsapi_base → code → POST /api/v1/auth/exchange服务端重新授权身份 + 上下文（不信任前端传入）→ X-WeCom-Context + 角色 + 可见字段集启用（W6 已验证）
会话存档回调/拉取GetChatData 主动拉取（seq 游标 / 5 天窗口）RSA+AES 两段解密 + msgid 幂等→ PreOrderWorkflow（自动捕捉段）暂缓（自动下单移出）
JS-SDK 配置GET /api/v1/wecom/jsapi-config双签名（企业签名 + 应用签名）→ S1 H5 初始化启用

企微 = 转接层：每个回调最终都映射为一次 HTTP API 调用（信号/查询/预订单动作），转接层不承载任何业务逻辑；因此「企微接入后」与「直接 HTTP」行为等价（scripts/fullchain 与 tests/l2_e2e 独立走通全部 HTTP 流程即企微接入的等价验证）。

5 · 0.1 特殊接入

5.1 仓库群升级企微群（A6）

  • 现状纠正：demo 现状「司机私聊仓管 → 转发凭证机器人」是错的（虹励与司机无直接沟通）；
  • 实际业务：两个外租仓库的仓管把回单统一发在群聊里 → 仓库群升级为企微群 → 凭证机器人从群里自动抓取/识别/登记归档；
  • 前置：虹励需先补仓库群现状截图，并把几个仓库沟通群升级成企微群（P2）；
  • 升级前备选：回单走「上传凭证」Tab 手动上传。

5.2 凭证机器人抓取（A2 兜底 + A6）

  • 回单：从企微仓库群自动抓取回单照片 → OCR 识别签收信息 → 匹配订单 → 登记归档（凭证 v3 只追加）；
  • 凭证兜底：只服务没有电脑操作场景的人（如餐馆类客户、在外跑的销售）；
  • 销售合同回传仍走机器人（销售常在外面跑、没机会对电脑）。

5.3 发群守门员（A3）

  • 任何内容发客户群前必须有销售点一次确认；确认记录 append-only 审计（GatekeeperConfirmed 事件）；
  • 先收紧后放行：0.1 全部强制，之后逐步释放自动化；「哪些内容可直发、哪些必须审核」规则表 P5 待确认。
