HTTP API · 0.1
全接口描述

本文档描述系统全部 HTTP API 接口：路径、方法、请求体、响应体、权限、幂等；并标注 0.1 需要的接口与暂不需要的部分。接口清单与 internal/api/server.go 路由定义一致（25 端点 + 15 个工作流信号；另含 /bridge、/assistant、/ops 三个 H5 页面路由）。销售助理闭环（v0.1 明确要求）：POST /api/v1/bridge/orders 代下单 → 飞书流续跑，GET /api/v1/bridge/orders 订单可查。接口与业务流程、企微回调的调用关系映射见 §5。

2 · 端点详述

GET/healthz0.1 启用
健康探测。响应 {"status":"ok"}；容器 healthcheck 用 wget -qO- http://localhost:8080/healthz。权限：无（探针）。
POST/api/v1/orders0.1 启用

用途：创建订单（人工下单 XS2 / 代下单 XSZL1-2 的 HTTP 落点）。授权预检（order.edit：owner + delegate + ops）→ 幂等启动 OrderWorkflow。

请求：JSON body 含订单要素（客户/明细/数量/单价/账期/合同/收货地址等）+ idempotency_key；头 X-User-Id（演示模式）或 X-WeCom-Context（S1 服务端校验）。

响应：201 订单创建 + 订单号（如 ORD-20260811-0109）；幂等：同键同 payload 返回既有资源；同键异 payload → 409；重复提交 → 409「订单已提交，请勿重复操作」。

权限：order.edit（销售本人/代办/商务 ops）；测试背书：L2-01/02/03、E2E FullChain 9 用例。

POST/api/v1/orders/{orderID}/signal/{signal}0.1 启用

用途：订单人工闸门信号（审价/终审/备货选仓/仓管/财务/发货/开票/例外/修改等 13 个信号，见 §3）。人工闸门不可绕过：Signal 只能通过受控载荷投递。

请求：JSON body 为对应信号载荷（如审价 verdict、发货数量 qty）；企微回调经 EventKey 翻译后调此端点（W5 已验证）。

响应：200 信号已投递；任务已决 → 409 幂等回执；无权限 → 403。

权限：按信号对应 permission（如 chairman-review = order.approve）；测试背书：L2-03/04/06/07/08/10/11/14、W5。

GET/api/v1/orders/{orderID}0.1 启用

用途：订单详情（BFF 字段投影 CQ-02/03）。仓管视图剥价（无单价/金额）；销售仅本人订单全字段；商务 ops 全字段；董事长决策全字段。

响应：订单头 + 明细 + 四节点状态 + 审批链状态 + 凭证列表 + 三金额（按投影）。

权限：order.view（owner/delegate/ops/admin/warehouse staff 剥价）；测试背书：L1-10 Projection、W6 S1。

GET/api/v1/orders/{orderID}/events0.1 启用
事件链回放（CQ-12 审计）。响应：append-only 事件序列（谁/何时/何因/结果）。测试背书：FullChainPaid 26 事件断言。
GET/api/v1/todos0.1 启用
待办检索（CQ-05，S4 工作台/催办）。按 assignee/kind/state 聚合：销售本人待办（XS4）、商务全量待办（SW3）、主管审价、财务例外、董事长终审。测试背书：L1-11、E2E TodosDuringFlow。
POST/api/v1/orders/{orderID}/shipments/{shipmentID}/evidence0.1 启用

用途：凭证追加（CQ-15 只追加不覆盖）。上传者：requester（销售）/ warehouse_operator（仓管）/ accounting（财务 · 0.1 主路径 A2）/ customer_contact（阶段二）/ robot（凭证机器人）；0.1 主路径：财务订单后台上传发票凭证（CW1）+ 凭证机器人登记回单（CG3）。识别登记字段 kind/source/invoice_no/amount_cents/tax_cents；金额守恒：开票金额 ≤ 已发货金额（超限 409）。

响应：201 凭证 vN 版本（追加）；重复版本 → 409；无权限 → 401/403（CONTACT 无 append_evidence）。测试背书：L1-16、L2-15、E2E EvidenceChain。

GET/api/v1/orders/{orderID}/shipments/{shipmentID}/evidence0.1 启用
凭证版本回放（有序 [v1, v2, v3...]）。审计/对账用。测试背书：EvidenceChain 有序回放。
POST/api/v1/preorders0.1 启用（人工确认段）

用途：创建预订单（智能下单 XS3）。msgid 幂等：UNIQUE(tenant_id, group_id, msg_id)。

响应：201 预订单 DRAFT-2026-xxxx；重复 msgid → 返回既有预订单；无权限 → 403（消息发送者 ≠ 归属销售/代办）。

测试背书：L2-12/13、E2E PreOrderChain/Ignore/EscalateAndConfirm。

POST/api/v1/preorders/{preOrderID}/signal/{signal}0.1 启用
预订单信号：preorder-confirm（确认，含修改后确认）/ preorder-ignore（忽略）。销售是唯一可确认角色（归属校验 SpiceDB + StaticChecker）；确认一次成单（订单幂等键防重复）；非 PENDING_CONFIRM → 409 幂等回执。企微回调 EventKey preorder:* 翻译至此。测试背书：L2-12、W5。
GET/api/v1/preorders/{preOrderID}0.1 启用
预订单查询（S2 确认态查询）。响应：候选字段（SKU/数量/价格/置信度）+ 状态。
GET/api/v1/wecom/jsapi-config0.1 启用
JS-SDK 双签名配置（ww.register 企业签名 + ww.agentConfig 应用签名）。S1 侧边栏 H5 初始化用。测试背书：W6 WeComS1Sidebar（双签名 + 协议白名单）。
POST/api/v1/auth/exchange0.1 启用
OAuth 身份/上下文交换（snsapi_base code → 服务端重新授权身份 + 客户/群上下文，不信任前端传入）→ 返回 X-WeCom-Context + 角色 + 可见字段集。测试背书：W6（code/chat/未知拒绝/context_token）。

2+ · 销售助理桥接端点（v0.1 明确要求）

GET/api/v1/bridge/auth-urlB2B_FEISHU_BRIDGE_ENABLED=true 时启用
飞书三方审批 OAuth 授权 URL（A1 代理方案）。响应 {"auth_url": "..."}；销售助理首次使用先授权。
POST/api/v1/bridge/callback同上
OAuth code 换 token（服务端按 X-User-Id 缓存，2h + 15m 重授权窗口）。
POST/api/v1/bridge/orders同上 · v0.1 明确要求①销售助理可以下单
销售助理代下单调用器：请求体含客户/明细/结算/合同/归属销售与代办人；桥接创建旧系统飞书订单（bridge.CreateOrder）→ 响应 201 提交回执。测试背书：TestBridgeHandlerEndpoints（auth-url/callback/create/list 全链）。
GET/api/v1/bridge/orders同上 · v0.1 明确要求②销售助理订单可查
桥接自建单台账（bridge_submissions，按租户时间倒序）：flow_id / 订单号 / 详情跳转 URL；无记录返回空数组不裸报错。测试背书：TestBridgeListOrdersAndUIs。

4 · 通用约定

约定内容
鉴权演示模式：X-User-Id / X-Role 头；S1 侧边栏：X-WeCom-Context 服务端签发校验（携带时生效，既有调用零影响）
授权每个业务副作用前 SpiceDB CheckPermission（FullyConsistent）；授权失败 401/403
幂等同键同 payload → 返回既有资源；同键异 payload → 409；跨租户同键互不影响
错误错误映射（Temporal 客户端 + LocalRunner 双模式）；业务错误给用户可理解文案（「数量超出应发量」而非裸状态码）
验证基线tests/l2_e2e 21 用例覆盖 13 端点 × 15 业务场景全绿；scripts/fullchain 22 步全链 demo（订单/凭证/预订单/待办/出站）
