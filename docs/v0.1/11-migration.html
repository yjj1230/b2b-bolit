迁移与数据同步 · 0.1
飞书 → 本系统 · 单向只读

0.1 的上线方式是不打扰现有流程：之前类似的流程跑在飞书上（三方审批流），0.1 只开放部分流程给商务同学用，原来的审批流不能停。我们采用数据同步的方式，让飞书侧的数据在本系统流里可见、可操作。本文档给出同步方案框架 + 程序员调研清单（原数据库结构 / 飞书多维表结构 / 飞书三方审批流部署），与既有 docs/02-architecture.html §8 数据迁移布局互补——§8 是「为未来迁移提前布局」的建表预留，本文档是 0.1 同步实施方案。

⚠️ 口径更新（D-013）：存量订单同步已裁决：v0.1 不做，归 v0.2 数据迁入；v0.2 数据正式迁入新系统，v0.3 全量数据迁完。本文是迁移方案框架，执行按 v0.2 / v0.3 排期。见 版本规划.html。

3 · 程序员调研清单（现场同事 · 三项调研）

调研任务 T1 · 原有数据库结构
调研目标产出
① 数据库类型/版本/部署位置（可访问性）；② 全部相关表清单与字段定义（orders/stock_prepares/shipments/invoices 及事件表）；③ flow_id/stage_id/instance_id/task_id 贯穿键的实际取值样例；④ 数据量级与增长速率；⑤ 是否有只读访问账号/权限表结构清单（字段/类型/约束/索引/样例行）；贯穿键样例；只读账号申请单

用途：确定增量游标字段（updated_at/seq）、映射字段来源、幂等键构造。

调研任务 T2 · 飞书多维表结构
调研目标产出
① 多维表清单（bitable_flow_records / customer_bitable_sync 及实际使用的表）；② 每张表的字段/类型/视图权限；③ 记录与订单/审批的对应关系（record_id ↔ flow_id）；④ 更新频率与数据规模；⑤ 飞书开放平台应用是否已建（app_id/secret 权限范围）多维表字段清单；record↔flow 映射样例；飞书应用权限清单（bitable:app 读权限）

用途：决定多维表是否作为同步源（或仅作对账参考）；bitable API 读取方案。

调研任务 T3 · 飞书三方审批流部署
调研目标产出
① 三方审批流的技术形态（自建应用/第三方平台/审批实例存储位置）；② 审批实例/任务的数据结构与状态枚举（待审/通过/驳回/撤回）；③ 审批人与节点映射（审价/终审/财务/仓管各闸门 assignee）；④ 审批结果如何影响订单状态；⑤ 是否有回调/webhook 可订阅（实时增量可能）审批流数据模型文档；状态枚举表；闸门 assignee 映射（对齐 08 §1.4 #8 缺口）；webhook 可行性结论

用途：审批状态同步映射（本系统 approval_tasks 视图）；实时增量方案可行性。

调研完成前，同步 Job 按「结构未知以配置驱动」原则开发：表名/字段/游标均可配置，调研结果回填配置即可，不阻塞 0.1 上线窗口。
已实现（2026-08-17）：cmd/sync + internal/sync（file/http 拉取器、列映射 MapRow、敏感字段剥离 SanitizeRow、批次校验和）+ repo.ApplySyncBatch（migration_batches 幂等锚点、orders 快照 upsert、事件搬运、legacy_flow_mapping 追溯）+ config/sync.example.json；单元测试 internal/sync/sync_test.go，L1 集成 repo TestV01SyncBatchIdempotent；V1 幂等/V4 敏感剥离已落地。
D-006（2026-08-17）：订单数据实体不再同步进本系统 PG 主数据表。 产品池/客户池/购销合同统一经 pgAPI 访问（products/customers 查增改、purchase-contracts 只读）； 本系统 PG 只保留流程引擎数据。飞书旧订单同步写入 orders.customer_id 时，该值必须是 pgAPI 客户 record_id，映射经 pgapi_entity_mappings 一次性回填。回填工具： go run ./scripts/pgapi_backfill -key $B2B_PGAPI_API_KEY （默认 dry-run，全匹配后加 -apply）。

4 · 同步策略（周期 / 实时 / 增量）

方案机制适用0.1 选择
周期性全量+增量每周期：全量对账（抽样/checksum）+ 增量拉取（updated_at > 游标）数据量小、时效要求宽松（分钟级）0.1 主方案（周期可配，建议 5m-1h）
实时/近实时飞书 webhook/事件订阅 → 即时触发增量需要秒级可见视 T3 调研结论启用（webhook 可用则升级）
纯增量仅按游标拉取变更数据量大0.1 数据量小，全量+增量更稳
  • 游标设计：按源表 updated_at（或自增 seq）+ 批次幂等（migration_batches checksum）双保险；
  • 首次全量：上线首跑全量快照 → 抽样核对 → 建立游标 → 进入增量循环；
  • 失败处理：批次失败重试 + 告警，不阻塞下一批次；连续失败超过 N 次 → 停止并人工介入（不静默丢数据）；
  • 对账：每日定时核对飞书 vs 本系统订单数/状态分布，偏差告警（L3 reconcile 脚本扩展）。

5 · 数据映射方案（飞书 → 本系统）

源（飞书）目标（本系统）映射要点
orders（状态快照链）orders（当前态）+ order_events（事件链）快照按业务主键取最后一条有效记录；事件优先搬运源 event_id/occurred_at/action/task_id（不得伪造审计链）；legacy_flow_id 落 orders
flow_id / stage_id / instance_id / task_idlegacy_flow_mapping以 order_id 为主脊；保存 flow_id、stage_code/seq、各阶段 legacy_instance_id/task_id 与目标实体——避免四阶段实例错误折叠
idempotency 原键 / create_fingerprint(tenant_id, idempotency_key) + payload_hash原键直接搬入（补租户前缀）；create_fingerprint → payload_hash，同内容不重复审批语义延续
stock_prepares + 事件stock_prepares + stock_prepare_items + 事件保留备货审批/到款/仓库分配边界；禁止压缩进 shipments（无法区分「已备货未发货」与「已发货」）
shipments + 事件shipments + shipment_items + 事件按源 stock_prepare_id 复合 FK 连接 STK→SHP；保留 batch_seq/split_flag/remaining_quantity
invoices + 事件invoices + invoice_items + 事件七任务节点 → approval_tasks(kind=INVOICE_*)；available_invoice_amount/qty → invoice_items 守恒基准（双维度，语义不变）
审批实例/任务approval_tasks（同步视图）stage_code + kind + assignee + verdict 映射；assignee 映射表调研后冻结（08 §1.4 #8）

凭证/回单文件evidence_versions + evidence/ 文件存储文件路径引用迁入，文件本体迁入加密存储；版本只追加
多维表记录legacy_bitable_mappings（只读归档）保留 flow/record/app/table 映射供对账；不作为业务事实源

6 · 敏感字段与边界

字段类别处置
身份标识（open_id / user_id / operator_open_id）进 PG 前映射为内部 user_id；Open ID 仅存加密映射表
访问令牌（approver_view_token 等 5 个 view_token）不迁入 PG（审批完成后令牌即失效，迁移时丢弃）
请求/响应体、审批表单原始 JSON只进 legacy_* 只读归档（加密列存储），不进业务表
原始聊天文本不迁移（业务库零留存原则；事件链只存意图特征与 archive_ref）
密钥/签名（EncodingAESKey、存档私钥）绝不迁移，新系统重新配置（KMS/环境变量）
回单/凭证文件加密存储（租户隔离 + SSE）；路径可解析 + 存在性抽样比对

验收证据：迁移后 PG dump 静态扫描（正则：open_id / token / secret / private_key 等模式）零命中；legacy_* 归档只读（不参与任何 workflow/通知/重试路径）。

7 · 验证与验收

#验证项方法
V1同步幂等同一批次重跑 → 无重复数据（migration_batches checksum）
V2数据一致抽样 N 条源记录 → 目标 PG 逐字段核对；每日对账脚本（订单数/状态分布）
V3审计可追溯同步写入产生事件（append-only）；批次日志留痕
V4敏感零残留PG dump 正则扫描零命中；归档只读验证
V5不打扰飞书同步期间飞书侧零写入（只读账号验证）；原审批流冒烟（飞书侧照常审批）
V6商务可操作虹励在本系统看到同步订单 → 完成备货/发货/开票操作（17 场景 walkthrough）
0.1 同步验收口径：V1-V6 全绿 + 调研清单 T1-T3 产出归档（回填 sync 配置）。0.2/0.3 再评估双向同步或整体替换飞书流程。
