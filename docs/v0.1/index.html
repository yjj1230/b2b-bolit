0.1 版以 ord_fulfill demo（已集成运营、产品、客户直接反馈）为现实需求裁决源，对既有文档体系（docs/01-09）进行大规模重构：12 个独立章节，覆盖双 graph、产品、交互、架构、业务流程、企微对接、数据库、API、测试、部署、迁移，以及新增的影子全流程预演。阅读顺序 = 编号顺序：先看双 graph 建立全局，再沿产品 → 交互 → 架构 → 流程 → 企微 → 数据库 → API → 测试 → 部署 → 迁移 → 影子全流程逐层落实。

⚠️ 发布口径更新（D-013 · 2026-08-20）：v0.1 实际开放 = 虹励（销售助理身份）桥接代下单 + 查自己的订单 + 影子新单实时重放；本文 02/06/07/08 章节中的商务履约（备货 / 发货 / 开票）与多角色入口是 demo 全量设计和后续版本资产，按 v0.2（商务 / 财务 / 仓管）、v0.3（销售 / 主管 / 董事长）开放，核心依据见 版本规划.html。
0.1 范围（A8 + D-008 双轨裁决）
仅虹励（销售助理身份）使用 · 08-21 前上线 · 不打扰现有飞书流程（原审批流不停；飞书侧单向只读同步，存量订单同步已裁决：v0.1 不做（归 v0.2 数据迁入））· 自动下单移出一期（智能下单人工确认段保留）· 锁库存暂不做 · 文档驱动迭代（一个文档进去，所有东西自动跟它同步）。
双轨发布：对外轨 A（虹励/客户可见：桥接下单、飞书流续跑、我的订单/状态回显）不变；新增影子轨 S（仅内部：完整状态机按 D-012 新单实时增量预演、收集覆盖/分歧/审计证据，零客户触达、零出站、零回写、可重建重放）。D-009 无托底 + 全节点覆盖/差异映射可接受；D-010 独立环境（自带 shadow-temporal）并运行到 v0.3 后撤销；D-011 多次发布验证线 + 六同原则保持近乎真实系统。
