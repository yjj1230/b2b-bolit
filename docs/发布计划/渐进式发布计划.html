B2B 订单履约系统 · 发布规划

渐进式发布计划 v0.1 → v0.4 → 取代飞书

每周一版 · 逐角色点亮业务流 · 数据范围渐进扩大 · 最终目标：以企微版流程取代飞书三方审批流。
每个版本迁移一批「办理动作」进入新系统；v0.4 后迁移两级终审，完成真相源切换，飞书三方审批流整体下线（保留历史归档）。

用户销售助手 → 商务 → 仓管·财务 → 销售 → 全员
流程覆盖下单 → 备货 → 发货·开票 → 全流程 → 含两级终审
飞书轨迹照旧 → 备货迁出 → 发货/开票迁出 → 仅剩终审 → 整体下线

2切换稳定性 · 五条铁律

「淡化飞书」不是切换开关，而是逐环节的渐进迁移。以下五条保证任何一步出错都能原地退回。

1真相单源迁移期间，业务状态机始终由旧系统推进（新系统办理 → 受信通道执行 → 飞书实例同步显示已办）；0.5 完成真相源切换（一次性数据迁移 + 逐日对账）后，新系统成为唯一真相源——这是「取代」的最后一环。
2执行权按环节迁移每个环节独立开关：开了，该环节在新系统办理；关了，立即退回飞书办理。环节之间互不影响。
3旧系统仅两处小改① 信息确认自动通过 + 独立审批人配置（v0.1）；② 受信办理通道（v0.2 起，一次改造四版复用）。不修任何历史问题。
4数据单向只读旧系统 → 新系统同步幂等批次，可重放、可停止；执行通道只推进状态、不触碰原始数据文件。
5每日对账 + 体验验收订单数/状态分布逐日对账；每版以「该角色体验清单」验收，迁移环节连续 N 天执行一致后才算稳定。
数据范围扩大规则：先「摘要 + 抽样核对」→ 再「全量 + 逐日对账」→ 最后「权限规则化」。每一层数据打开前，先由目标角色 1 人试用一周，人工核对无误后才放量。

3版本详情（效果视角）

每个版本描述「谁、从此能做什么、飞书退到什么程度」；技术动作仅一行概括。

v0.1

销售助手上线：企微端下单，飞书审批照旧

第 1 周 · 用户：销售助手（虹励，唯一）
发布后效果
  • 用户：销售助手虹励一人先用起来——在企微侧边栏/群聊确认卡里下单（人工下单、代下单），无需再打开飞书创建页。
  • 流程覆盖：下单 → 信息确认自动通过（无需她点）→ 主管/董事长审批照常在飞书推进 → 她在新系统随时看到订单走到哪一步。
  • 体验闭环：下单成功即见「已进入审批」；被驳回 → 看到原因 → 一键复制重提；点「查看完整流程」直达飞书侧全流程详情页。
  • 对业务零扰动：审批人看到的仍是标准飞书待办；飞书 H5 老用户的下单链路完全不变。
飞书取代进度：本期仅「下单入口」迁入新系统，审批中心的人工待办范围不变——这是淡化的起点，不急于推进。
迁移的环节下单（创建入口）· 信息确认（自动通过）
数据范围仅「自建单」——不拉取存量全量，零历史包袱
技术动作下单桥接模块（OAuth 授权 + 调用旧系统创建接口 + 幂等回写）；旧系统小改 ①（自动确认 + 独立审批人配置）
验收 / 回滚体验闭环 6 项通过；关闭「下单开关」即退回，飞书侧无任何残留
v0.2

商务接入：备货环节迁入新系统，飞书首个环节淡出

第 2 周 · 用户：+ 商务
发布后效果
  • 用户：商务角色接入新系统（虹励的商务身份 + 后续商务同事逐批加白名单）。
  • 流程覆盖（首个执行迁移）：备货环节（商务填写发货仓）在新系统直接办理——商务看到「待我备货」清单，在新系统完成选仓/计划发货日期/收货信息/通过或驳回，不再需要打开飞书；飞书审批中心该环节自动显示已办，主管/董事长等后续节点照常在飞书推进。
  • 商务视角升级：订单全景总览（所有订单一屏看状态/节点/处理人），为对账与调度提供统一视图。
  • 数据范围首扩：同步扩到备货相关订单——抽样核对备货字段与状态映射后放量。
飞书取代进度：备货环节（商务填写发货仓）的人工待办从飞书审批中心消失——飞书侧首次出现「环节级淡出」，并作为后续环节迁移的样板。
迁移的环节备货 · 商务填写发货仓（执行迁入新系统）
数据范围+ 备货单摘要（stock_prepares）· 按商务 or-sign 归属过滤
技术动作商务身份接入；旧系统小改 ②（受信办理通道：新系统办理 → 旧系统状态机推进 + 飞书实例同步）；同步扩展备货实体；权限规则
验收 / 回滚商务体验清单 + 备货单对账零偏差 + 执行一致性校验（新系统办理结果 = 旧系统状态机结果）；关闭「备货环节开关」即退回飞书办理
v0.3

仓管与财务接入：发货 / 到款 / 开票环节迁入新系统

第 3 周 · 用户：+ 仓管 · + 财务
发布后效果
  • 用户：仓管（含各外租仓库）、财务接入新系统。
  • 流程覆盖（执行迁移）：发货环节（仓库发货、上传回单/完成信息）与财务环节（确认到款、开票申请）在新系统直接办理——仓管看到「待我发货 / 待回单」清单（按仓库维度过滤），在新系统完成发货数量/物流/回单上传；财务看到「待确认到款 / 待开票」清单，在新系统完成到款确认/开票申请。两者都不再需要打开飞书。
  • 多角色协同视角：每笔订单在一条时间线上展示「谁在办、办到哪」；仓库维度数据（发货/回单）首次进入新系统。
  • 数据范围第三扩：同步扩展发货单与开票单摘要——按仓库/供方维度抽样核对后放量。
飞书取代进度：发货、回单、到款确认、开票申请四类人工待办从飞书审批中心消失；飞书侧剩余：信息确认（自动）、主管审批、董事长终审、盖章回传、开票信息填写等销售环节。
迁移的环节发货（仓库发货/上传回单）· 财务（确认到款/开票申请）
数据范围+ 发货单 / 开票单摘要（shipments / invoices）· 按仓库、款到维度过滤
技术动作仓管/财务身份接入；受信办理通道扩展两类环节；同步扩展两实体；视图与权限规则
验收 / 回滚两角色体验清单 + 发货/开票对账零偏差 + 执行一致性校验；环节开关独立回滚
v0.4

销售全员接入：全流程迁入新系统，飞书仅剩两级终审

第 4 周 · 用户：+ 销售（全员）
发布后效果
  • 用户：销售全员接入——每个人在企微端自助下单/代下单，查看自己的客户订单全景（按销售归属裁剪）。
  • 流程覆盖（销售环节执行迁移）：信息确认（本人办理）、开票信息填写、客户订单盖章回传在新系统直接办理；发客户群消息（守门员确认：任何内容发客户群前销售点一次确认，全程留痕）——销售不再需要打开飞书办理任何环节。
  • 数据全量就绪：存量订单全量同步完成（首跑全量 + 逐日增量对账）；可见性按「角色 × 环节」权限矩阵裁剪。
  • 里程碑：除主管/董事长两级终审外，全部业务环节的办理动作已迁入新系统——飞书审批中心进入「仅剩两级终审」状态，为 0.5 的最终淡出备齐数据底座。
飞书取代进度：飞书审批中心只剩主管审批、董事长终审两级人工待办（审批人继续在飞书操作）；其余环节在审批中心仅显示「已办」结果。这是取代前的最后状态——0.5 完成两级终审迁入与真相源切换后，飞书三方审批流整体下线（第 6 节）。
迁移的环节信息确认 · 开票信息填写 · 盖章回传 · 发群守门员
数据范围全量订单（存量+增量）· 权限矩阵裁剪 · 逐日对账
技术动作销售批量身份接入；同步收官；守门员模块；权限规则全量；受信办理通道收口

8需要你知晓的风险与待决项

项说明影响与处置
审批人配置现状旧系统默认审批人配置中，主管/董事长位置指向了不处理业务的程序员账号新系统订单使用独立审批人配置（真实主管/董事长）；默认配置维持现状不动
