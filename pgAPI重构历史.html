1 · 本次任务的来龙去脉

1.1 用户最初指令

用户要求充分理解 spec/pgAPI-接口文档.md（v1.1，2026-08-17），基于项目迭代机制对 b2b_pilot_v3 做一次大调整，把数据库访问分为两大块：

  • 流程引擎需要的数据库读写：直接读写 PostgreSQL。
  • 订单数据（非流程相关，指数据信息实体）：通过 pgAPI 访问。

用户明确表示这是巨大调整，要求先深入理解现有项目迭代机制、做深度分析，并“做到无法继续为止再确认”。

2 · 项目迭代机制与当前控制面状态

2.1 机制要点

项目采用 ECM 1.0.0《证据收敛式项目迭代机制》。关键规则：

  • 语义 / 实现 / 验证三态必须分开维护，不能用单一“状态=完成”。
  • spec/docs/demo/code/tests 更新要进入 INGEST → NORMALIZE → DIFF → IMPACT → ROUTE → VERIFY → BASELINE 循环。
  • 语义变化、范围变化、R2-R3 冲突、owner 不明确必须 needs_human，用 question_packet（最多 3 项）请人裁决。
  • 机制 PROPOSED 时进入 BOOTSTRAP_DIAGNOSTIC：只允许只读盘点、提出/执行用户已授权的控制面迁移；不得伪造 ACTIVE、不得宣布 PASS。

4 · 现状盘点与影响分析结论

4.1 原状（调整前）

  • 所有持久化走 internal/repo 直连 PostgreSQL，包括本地 customers、products 主数据。
  • workflows.Store 接口混入了主数据方法 GetCustomerGrade。
  • repo.GetCustomerGrade 执行 SELECT grade FROM customers。
  • SeedDefaultWorld 会播种 cust-0001/cust-0002/prod-c68/prod-d90 到本地主数据表。
  • 本地 PG 有 7 处对 customers/products 的外键： orders.customer_id、 order_items.product_id、 stock_prepare_items.product_id、 shipment_items.product_id、 invoice_items.product_id、 inventory_items.product_id、 customer_contacts.customer_id。
  • 订单校验路径：ordValidateStep 经 Activity 读本地客户等级；ordGradeStep 再次读等级做 C/D 分流。
  • 合同生成段 CustomerName 是占位 "客户"，产品只检查 ProductID != ""。
  • 大量测试与 demo 硬编码 cust-0001/cust-0002/prod-c68/prod-d90。

4.2 影响半径结论

影响域结论
repo 层必须把 customers/products 访问从流程 Store 契约中移除；流程表 ID 语义从本地主键改为外部 record_id。
workflow 层客户等级、客户名、产品存在性校验必须经新 Provider/Activity，不能在工作流里做 HTTP。
数据库必须先去除 7 处 FK，否则流程表无法写入 pgAPI record_id；本地主数据表降级 legacy 不删除。
旧数据旧 cust-*/prod-* 需要一次性映射回填为 pgAPI record_id，否则新校验查不到旧订单实体。
测试本地 ID 作为“pgAPI record_id 的测试替身”继续使用；真实 pgAPI 测试需独立环境。
部署worker 生产环境必须配置 B2B_PGAPI_*；docker-compose 已要求 API Key。

6.3 关键实现语义

  • 生产路径：cmd/worker 必须配置 pgAPI Key；Activities.ValidateOrderData 会校验客户存在、客户等级、每个明细 product_id 存在。
  • 本地/测试路径：NewDemoMemoryProvider 提供 cust-0001→A、cust-0002→C、prod-c68、prod-d90 作为 record_id 替身；这些旧字符串已不再是本地主键语义。
  • 兼容桥：Data == nil 时 Activities 回退到 FakeStore 的 GetCustomerGrade，用于未迁移的旧测试。这是临时桥，不是生产行为。
  • 写接口：pgapi.Client 与 orderdata.Provider 已实现 CreateCustomer/UpdateCustomer/CreateProduct/UpdateProduct；但 b2b_pilot_v3 尚未新增对外的产品/客户管理 HTTP 端点。
  • 合同：流程仍生成 HT-…；pgAPI 合同查询能力已具备但未接流程。
  • 迁移 007：只删 FK + 建映射表 + 标 legacy；不改写旧数据。旧 ID 改写由 backfill 工具完成。
