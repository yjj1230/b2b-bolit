RHCRM 数据源架构说明

客户池 · 产品池 · 订单 三类数据在三个订单审批系统中的来源与统一
版本 v4.0 日期 2026-08-18 范围 数据源 · 数据流向 · 同步机制 · 最终部署
1目标

三个订单审批系统涉及三类核心数据：客户池、产品池、订单。为避免多数据源并存、难以管理，规划如下统一策略：

  • 客户池 / 产品池：以 PostgreSQL 为准（飞书原生、飞书三方审批系统从飞书同步而来，企微订单审批系统直接使用 PG）；
  • 订单：统一汇入 PostgreSQL 购销合同表，作为唯一订单数据源。
2架构总览

※ 数据生产者：飞书原生审批、飞书三方审批（写飞书多维表格）；企微订单审批（订单数据经 pgAPI 写入购销合同表）。同步：飞书侧三张核心表 = 事件订阅同步（Webhook）。数据消费者：企微订单审批（经 pgAPI 读写 PG）、订单查询。

5同步机制

5.1 同步任务

飞书多维表格支持记录变更事件（drive.file.bitable_record_changed_v1，Webhook 推送），客户池、产品池、三方审批流程表三张核心表的变更实时推送同步：

飞书多维表格（客户池 / 产品池 / 三方审批流程表）
↓ 记录变更（新增/修改/删除）推送 Webhook
Webhook 回调服务（rhcrm_webhook · 公网 https://api.renheng.com/feishu/webhook）
↓ 携带 table_id / record_id / action → 触发对应表同步（20 秒防抖）
同步处理（受控字段映射） → 写入 PG
同步任务数据来源 → 写入目标触发方式状态
客户池 / 产品池同步 飞书客户池表/产品池表 → PG（受控业务同步，白名单字段） 事件订阅同步 已上线
三方审批订单同步 飞书三方审批流程表 → PG购销合同表（44 字段映射，按申请编号去重） 事件订阅同步 已上线
企微订单同步 企微订单审批系统订单 → PG购销合同表（经 pgAPI 新增接口，字段映射） 企微经 pgAPI 写入（企微订单审批系统经 pgAPI 新增接口写订单至购销合同表） 待 v3 上线后启用

※ 本架构仅覆盖客户池、产品池、购销合同表三张核心表，同步统一采用事件订阅（Webhook）方式。

7关键原则
  • PG 购销合同表是唯一订单源：三个系统的订单都汇入，不做多数据源。
  • 仅覆盖三张核心表：本架构只涉及客户池、产品池、购销合同表，同步统一采用事件订阅（Webhook）方式。
  • 事件订阅同步：飞书侧数据变更经 Webhook 实时同步。
  • 只进 PG：同步只写 PG，不回写飞书（飞书侧保持现状）。
  • 幂等同步：按申请编号/记录 ID 增量去重，重复运行或重复事件不产生脏数据。
  • 只读 + 仅允许新增：购销合同表经 pgAPI 仅开放查询与新增，修改/删除受保护（唯一订单源受控）。
  • 飞书三方审批系统不改动：只做数据同步，不改生产代码。
