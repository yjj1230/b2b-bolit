# 销售助理下单表单调整（2026-08-24）

## 1. 裁决与范围

本需求以产品经理在 `ord_fulfill/app/index.html` 的 2026-08-22 调整及 2026-08-24 提供的完整网页端截图为交互参考，并以项目负责人 2026-08-24 的补充裁决为最终口径。

`ord_fulfill/app/index.html` 是产品 Demo，仅用于确定网页工作台布局、字段、枚举与交互；生产页面由当前仓库的 `internal/api/assistant_ui.html` 通过 `/assistant` 路由提供，正式开发、测试和发布均以该生产页面为准。

### 1.1 LIVE 范围

- 销售助理从工作台进入时，先选择归属销售，再在该销售的客户范围内选择客户。
- 客户群入口继续由群上下文锁定归属销售与客户。
- 网页工作台保留顶部导航、人工下单标题、上下文提示及右上角“提交订单”按钮。
- 生产页面先展示「代下单归属（先选）」控制区，业务表单按「订单信息 → 商品明细 → 收货方式 → 结算方式」平铺展示；订单备注归入订单信息，不单独设置“补充说明”区块。
- 老客户命中档案后，预填供方、客户等级、税号、收货地址、收货人和电话；预填字段允许人工核对修改。
- 销售员、客户名称、供方、指定收货人和收货地址支持搜索选择；客户、供方、收货人和地址允许按业务约束手工填写。
- 商品明细包含产品型号、数量、单价、合计、包装类型、打包备注、规格、是否需要质检报告、到货时间和删除操作；产品型号支持行内清空，单价支持四位小数。
- 币种显示为人民币 (元)、美元 (USD)、欧元 (EUR)，提交值分别为 CNY / USD / EUR，金额表头和总计单位随选择同步。
- 正式订单仍通过既有 v0.1 Feishu Bridge 写入旧系统，旧飞书审批流继续执行。
- 迁移以 `pilot_v3` 当前安全基线为准：保留严格企微 OAuth、短时上下文过期、服务端身份回填、跨系统客户 `record_id` 解析和新客户归档，页面不得提供硬编码用户身份。

### 1.2 DEFERRED / 隐藏范围

合同能力本期整体隐藏，不进入 LIVE 操作路径：

- 不展示「新增合同 / 选择框架合同」。
- 不展示合同上传和合同编号。
- 不解析合同，不根据合同回填或锁定字段。
- 销售助理页面不调用购销合同搜索接口。
- 后端既有合同兼容字段与只读主数据接口保留，不删除、不扩展；页面提交不携带合同值。

## 2. 能力问题（CQ）

- CQ-P01：工作台入口是否仍要求先选择归属销售，并限制客户选择范围？
- CQ-P02：客户群入口是否仍锁定群上下文中的销售与客户？
- CQ-P03：老客户命中后，客户档案字段是否正确预填且可人工修改？
- CQ-P04：页面是否没有任何合同入口，并且不会调用购销合同接口？
- CQ-P05：没有合同信息时，订单是否能够正常提交到既有桥接链路？
- CQ-P06：商品新增字段是否通过现有旧系统契约兼容传递？
- CQ-P07：CNY / USD / EUR 是否按用户选择值提交，金额单位是否同步展示？
- CQ-P08：生产页面是否与网页端参考保持同一布局、字段顺序和交互口径，同时保留归属销售、授权身份与客户权限约束？

## 3. 局部操作图

```text
销售助理进入工作台
  → 选择归属销售
  → 搜索授权客户 / 新建客户
  → 客户档案预填
  → 填写订单信息
  → 填写商品明细
  → 填写收货方式
  → 填写结算方式
  → 人工核对并提交
  → /api/v1/bridge/orders
  → 旧系统 /external-orders/create
  → 新系统记录桥接台账
```

## 4. 架构影响

### 4.1 受影响

- `internal/api/assistant_ui.html`：网页工作台结构、右上角提交、字段采集、搜索选择、客户预填、币种与商品交互。
- `internal/api/bridge_handlers.go`：接收结构化质检要求并兼容映射到旧系统现有字段。
- UI smoke、bridge handler、bridge client 测试。

### 4.2 不受影响

- `internal/domain`
- `internal/workflows`
- `internal/repo`
- PostgreSQL migrations
- SpiceDB schema
- 影子轨状态机与信号映射

## 5. 验收 Oracle

1. `/assistant` 页面包含代下单归属控制区，以及订单信息、商品明细、收货方式和结算方式四个业务区块；提交订单按钮位于表单标题区右上角。
2. 页面源码和运行时均不存在合同上传、合同选择、合同编号控件。
3. 页面不包含 `/api/v1/orderdata/purchase-contracts` 调用。
4. 订单信息包含销售员、代办人、客户名称、税号、是否自提、供方和订单备注。
5. 销售员、供方、指定收货人和收货地址具备搜索选择能力，且客户档案带出值仍可人工修改。
6. 商品行具备产品型号、数量、四位小数单价、合计、包装类型、打包备注、规格、质检报告、到货时间、清空和删除能力。
7. 币种显示人民币 (元)、美元 (USD)、欧元 (EUR)；选择 CNY / USD / EUR 时，请求体分别发送对应代码，表头和总计单位同步。
8. 旧系统 multipart 中不出现空合同编号；商品兼容字段和特殊规格要求正确传递。
9. 既有销售归属、客户上下文、OAuth 与 `B2B_V01_` 幂等键行为不回归。
10. 页面脚本语法检查、UI smoke、bridge handler 和 bridge client 回归通过；浏览器运行时无合同文本、合同请求和控制台错误。
