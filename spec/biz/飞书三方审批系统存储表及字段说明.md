# 飞书三方审批系统存储表及字段说明

> 本文档仅说明系统存储结构，不包含任何订单、客户、人员或审批业务数据。

## 一、存储方式说明

当前项目没有使用传统 MySQL、SQL Server 等关系型数据库。系统核心业务数据主要以 **JSONL 追加式数据文件** 保存：一行是一条 JSON 记录，业务状态变化时追加新记录。因此，本文中的“存储表”是为了便于理解而使用的统一称呼，实际对应项目中的 JSONL 数据文件。

## 四、使用注意事项

1. 同一业务编号可能在追加式文件中出现多条记录，通常代表该业务对象在不同时间的状态快照，不应简单按重复数据处理。
2. 查询当前状态时，应按照业务主键筛选，并以最新更新时间或最后一条有效记录为准。
3. `*_events` 文件用于记录流转过程和操作轨迹，主业务文件用于保存业务对象状态，两类文件用途不同。
4. 字段中包含的 Open ID、User ID、访问令牌、文件路径等属于敏感技术信息，实际导出或共享业务数据时应进行脱敏。
