怀疑者层设计
把怀疑机器化，把注意力聚焦

在「确定性验证」与「人类判断」之间，补上第三根支柱：从数据中学到的怀疑——专为项目而存在的小专家模型与超规则系统，不替代 review，而是让每一次人类注意力都花在最可能出错的地方。

承《ZK-GE 闭环验证方案 v2》 项目：b2b_pilot_v3 2026-08-08 单文件、自包含 HTML

核心论点（三句话）：
① 小专家模型与超规则系统不是外挂，而是补完 v2 体系唯一还靠人的环节——怀疑的来源；
② 怀疑者只分配注意力与生成挑战，永不进入 pass/fail 的布尔逻辑；
③ 真正有效的不是「消灭 review」，而是「机器聚焦 + 人类仲裁」——这比全面 review 更强，因为全面扫 = 每个点都浅。

空白一 · 反刍的最后一公里

R1-R8 教训（「事务内禁止查 pool」「幂等键要带租户维度」）目前由人总结、人手写成图约束。若能把「缺陷 → 候选规则」机器化，设计反刍就真正闭环了。

空白二 · 未知未知无机器来源

确定性验证只能查「已知问题」；「没想过的问题」（规格投机、未建模风险、语义偏差）目前只靠人脑。统计信号是唯一能在未知侧给出线索的机器手段。

空白三 · 注意力没有预算

G1/G2 面对全部证据与全量变更，没有「哪里最可疑」的优先序。人类的验证注意力是稀缺资源，没有分配机制 = 全面扫 = 每个点都浅。

审计结论：v2 已把「验证已知」做成体系；怀疑者层负责把「发现未知」与「分配注意力」机器化。它不是 v3 的推倒重来，而是 v2 的自然补完——补的是「怀疑」这一环。

01概念校准：怀疑者（Skeptic）不是验证者（Verifier）

整个设计的第一条铁律：模型和规则系统的输出永远不是结论，而是「往哪看」的提示。

支柱性质回答的问题输出状态
验证者 Verifier确定性已知问题有没有？pass / fail / invalid已有：编译器、图约束、守恒、变异、模型检查
怀疑者 Skeptic统计性未知问题最可能在哪？suspicion score + 候选规则本设计新增
仲裁者 Human Gate决策性接受还是拒绝？accept / reject / conditional已有：G1 / G2

为什么怀疑者不能成为验证者（五条理由）

概率性

模型输出是分数与分布，有假阴/假阳；把它写进 release_allowed 的布尔合取，等于把发布决策押在统计侥幸上。

可对抗

实现域一旦知道模型特征，就可定向构造「特征上正常、语义上错误」的变更——统计信号会被博弈，确定性检查不会。

分布漂移

项目形态（新模块、新语言、新需求域）变化时，训练分布失效，模型静默失真——需要元层的漂移检测。

无 oracle 语义

模型学到的是相关性（correlation），不是业务语义（causation）。「统计上可疑」不等于「业务上错误」。

解释性

仲裁者必须能理解「为什么可疑」才能决策；黑箱分数无法支撑 G2 的职责——这是设计对可解释性的硬要求。

铁律：怀疑者的输出只能影响两件事——① 人类注意力的分配（G1/G2 的聚焦点与顺序）；② 挑战域的生成（对可疑处定向构造隐藏测试、故障注入、变异）。它永远不能直接授予绿灯。

02方法论基础：注意力经济

为什么「聚焦 review + 机器兜底」强于「全面 review」——这是本设计的元洞察。

全面 review 的有效性可以写成一个朴素等式：

策略有效性成本短板
全面 review（人扫全部代码/设计）注意力 ÷ 代码量，随规模衰减O(代码量)，昂贵人类注意力有限，全面扫 = 每个点都浅；规模一大有效性趋零
纯机器验证（只有确定性检查）只覆盖已知问题O(验证运行)，便宜未知未知漏光；同源自证无解
聚焦 review + 机器兜底（本设计）注意力 ÷ 可疑点集，可疑点集被机器压缩O(验证) + O(可疑点)依赖怀疑者的查全率；需要双门纪律防幻觉

机制上，怀疑者层 = 挑战生成器的进化。在 ZKP 协议结构里，Challenge 组件从「静态挑战集」（人写的测试用例）升级为「自适应挑战」：

flowchart LR CQ["CQ / 规约"] -->|静态挑战| T1["测试集<br/>(人写, 已有)"] GR["实现图 + 运行图"] -->|特征| SK["怀疑者层<br/>小模型 × 超规则"] SK -->|suspicion 排序| T2["定向挑战<br/>隐藏测试 · 故障注入 · 变异"] SK -->|可疑点 top-K| G2["G2 人类仲裁<br/>只审最可疑处"] T1 --> V["确定性验证器"] T2 --> V V --> E["证据图"]

与 ZKP 的关系：v2 说「ZKP 真正有效的是把交付改造成先承诺、后挑战、证据绑定、独立验证、风险决策的协议」。怀疑者层把「挑战」这一步从静态推向自适应——挑战的质量不再只取决于人写测试时的想象力，还取决于机器从历史经验中学到的怀疑。

03小专家模型：四个候选，按优先级排

「专为项目而存在」= 特征来自本项目图与 git，训练数据来自本项目历史缺陷。诚实前提：现有标注量决定了第一代必须是轻模型 + 特征工程。

3.3 模型细节与评估纪律

M1变更风险排序器

训练标签：R1-R8 + 注入缺陷 = 1；普通提交（可抽样 = 0）。评估：时间序列划分（前 80% 训练，后 20% 验证，防泄漏）。用途：G2 面板排序、挑战生成优先级、R0/R1 自动发布的弱信号。验收基线：对历史缺陷的 top-20% 召回率 ≥ 80%。

M2假绿检测器

训练标签：现有 168 测试的变异分数（运行变异测试获得，一次成本换长期收益）。用途：把「最可能假绿的测试」排到补测队列顶部——让测试闭环从「覆盖没覆盖」进化到「测了是否真的有用」。

M3漂移预筛器

用途：roundtrip 的预筛。现在 15 个 CQ 全查可行；未来 CQ 增长到 50+ 时，用嵌入相似度把「最可能漂移的 CQ」排前面，人工只复核 top-K。注意：这不是 NLI 门禁，是排序器。

M4异常边检测

用途：v2「抽图盲区」威胁的统计侧补偿——动态调用、运行时注入、消息路由逃出静态图，但会在运行图里留下与历史分布不同的统计痕迹。输出异常边清单进入 coverage debt 评估。

评估纪律（防自我欺骗）：① 模型评估集与训练集必须时间隔离，禁止随机划分；② 每个模型版本绑定评估报告（精度/召回/分位数校准）入证据；③ 模型上线前过 G1-Skeptic 门（见 §07）：评估集、误报预算、失效条件三者齐备才允许进面板。

04超规则系统：三层结构 + 双门纪律

「heuristic learning 范式」落成三层：执行层已有，归纳层与治理层新增。这是设计反刍的机器化——v2 的反刍是「事件→claim」，这里补上「事件→规则」。

4.1 三层职责

层职责形态状态
R0 执行层规则确定性执行，输出 pass/failOPA/Rego 或等价规则引擎 + 图约束查询已有（v2 §09 policy engine）

4.2 双门纪律（防幻觉规则）

门一 · 历史回放

候选规则必须在历史缺陷语料上回放：召回率 ≥ 阈值（如对 R1-R8 召回 ≥ 60%），且不误伤既有绿灯证据（对 300 正例误报率 ≤ 1%）。回放报告随规则入库。

门二 · 人类确认

规则必须带自然语言解释，且解释能映射回业务概念（守恒 / 幂等 / 授权 / 事件链之一）——归纳 ≠ 理解，统计巧合的规则必须有语义锚点，由架构师签字生效。

与「规格投机」的对称性：v2 防的是「AI 为了通过而改规格」；超规则系统要防的是「AI 为了抓错而发明规则」。两个方向的防御机制相同——规则/规格变更都要人类闸门、都要使旧证据失效、都要可回滚。

5.3 挑战域扩展

定向挑战生成

M1 高风险的变更集 → 挑战域定向生成：隐藏测试、故障注入、变异体，围绕其风险特征构造，而不是均匀撒网。

假绿复核队列

M2 低可信度的测试 → 进入「复核队列」：补断言、补负例、或替换为属性测试；复核结果回填 M2 训练集。

漂移复核清单

M3 高可疑的 CQ → roundtrip 时人工只复核 top-K；复核结论（漂移/未漂移）成为 M3 的新标签。

异常边处置

M4 异常边 → 进入 coverage debt 评估：归属已知盲区（记录）或触发新约束规则（走 R1 归纳）。

06威胁模型与 TCB 扩展

怀疑者层自身是新的风险面——按 v2 的原则：保证强度不会超过最弱组件。

6.1 威胁模型新增四行

新增威胁典型失效控制
分布漂移项目形态变化（新模块/新语言/新需求域），模型静默失真，可疑度排序失去意义漂移检测器（特征分布监控）+ 模型失效条件 + 定期重训触发
对抗样本实现域构造「特征上正常、语义上错误」的变更骗过模型模型输出不进门禁；特征透明化；定期用对抗样例评估模型鲁棒性
规则过拟合归纳规则只匹配历史缺陷形态，对新缺陷无召回历史回放门 + 保留的对抗语料定期评估 + R2 计数器驱动降级
训练集泄漏评估集混入训练集，精度虚高时间序列划分硬规则；评估报告绑定数据版本摘要

6.2 TCB 新增四个组件

组件职责必须登记
特征提取器图/git → 特征向量id + version + digest + owner + self_test
模型推理器特征 → suspicion score同上 + 评估报告摘要
规则归纳器缺陷语料 → 候选规则同上 + 语料版本摘要
规则库生效规则 + 元规则 + 计数器同上 + 变更需走双门并作废旧证据

6.3 保证等级的影响

L0-L4 定义不变。怀疑者输出属于 L1/L2 层级的「信号增强」：它让结构验证与行为验证更有针对性，但不把任何 claim 从 L2 升到 L3/L4。升等级仍然只能靠确定性手段（运行验证、形式化内核）。

07决策门禁修正

release_allowed 的布尔逻辑保持不变；怀疑者只改变「人类看什么」与「挑战生成什么」。

)
challenge_plan = generate_targeted(    # 供挑战域定向
  suspicion_report ∩ verifier_gaps
)

7.1 G1 扩展：怀疑者上线门（G1-Skeptic）

项要求
评估集时间隔离的验证集 + 评估报告（精度/召回/分位数校准）
误报预算每模型每周期允许的最大误报数，超预算自动降级为「仅提示」
失效条件分布漂移阈值、特征缺失阈值、评估分数下限
职责分离模型训练者与门禁批准者不得为同一人/同一 AI 上下文（对齐 v2 独立性原则）

7.2 G2 扩展：剩余怀疑度

面板新增内容禁止的替代指标
可疑点 top-K本次变更按怀疑度排序的前 K 项，每项带解释与证据引用模型自评「低风险」的绿色徽章
模型健康度每个模型的评估分数新鲜度、漂移指标、误报计数器「模型已运行」状态灯
规则效果每条生效规则近期的抓到数 / 误报数规则总数、规则库「全绿」

K 的选择 = f(风险等级, 可疑度分布, 规则置信度)——R0/R1 可以 K=0（全自动），R2 至少 K≥1 且必须有人类仲裁，R3 保持全部人工。

08落地路线：先证明怀疑者抓得到错

延续 v2 第 10 节的原则——每轮验收都用已知缺陷、变异或故障注入来验证验证者本身；怀疑者层同样适用。

Round范围交付硬验收
6 · 怀疑者骨架缺陷语料 + 特征 + M1 v0结构化缺陷语料库（R1-R8/F1-F6/300 用例负例/注入缺陷）；特征抽取流水线（图+git，不读代码）；M1 v0（GBDT/逻辑回归）；G2 面板接入可疑度排序对历史缺陷 top-20% 召回 ≥ 80%；时间隔离评估成立；面板只展示可疑度、不展示模型绿灯
7 · 超规则原型归纳器 + 双门R1 归纳器 v0（决策树/RIPPER 式）；候选规则评审工作流；历史回放门自动化；R2 计数器骨架注入 3 个历史缺陷形态的变体，归纳器产出至少 1 条命中候选规则且通过双门；回放门能拒绝 1 条统计巧合规则
8 · 闭环验证怀疑者自身被验证构造「确定性验证全绿、语义错误」的注入缺陷集，验证怀疑者能否抓出注入 ≥ 10 例，M1+M2+M3 联合检出 ≥ 60%，且每例都有可解释特征；失败案例进入语料库
9 · 数据飞轮持续化每次 incident/偏差自动结构化入语料；模型周期重训；规则计数器驱动治理两个连续里程碑的语料增长率、模型评估分数不倒退、误报计数器在预算内

建议节奏（对齐 v2 的 90 天框架尾部）：Round 6 约 2 周（数据与特征是大头），Round 7 约 1.5 周，Round 8 约 1 周，Round 9 进入常态化。总增量控制在 4-5 周内，不抢占业务里程碑的关键路径。

09边界与结论

怀疑者层能给你什么、不能给你什么——必须同样诚实。

它能给你的

① 把稀缺的人类验证注意力聚焦到最可疑处，让「不读代码」从「碰运气」变成「有先验」；② 把设计反刍的最后一公里（教训→规则）机器化；③ 给「未知未知」一个统计侧的探测源；④ 让挑战域从静态走向自适应。

它不能给你的

① 正确性声明——概率输出永远不是证明；② 免于需求责任/oracle 责任/风险责任（v2 结论不变）；③ 让 R2/R3 系统完全无人把关——它只改变人类把关注哪里，不改变人类必须存在；④ 对「模型自身正确」的保证——怀疑者也要被怀疑（Round 8 的意义）。

五条诚实边界（写进哲学）

#边界含义
1概率输出 ≠ 正确性声明模型分数永远不能成为独立硬门禁（R0 除外），只能改变注意力分配与挑战生成
2数据稀缺是硬约束第一代必须是轻模型 + 特征工程；先建特征流水线与评估框架，数据飞轮转起来再加深
3项目专用 = 项目过拟合单仓库训练的模型会过拟合本项目形态；需要元层的漂移检测，形态变化时模型降级而非静默失真
4归纳 ≠ 理解规则必须有解释、有回放验证、有人类确认，否则就是带统计伪装的幻觉
5不替代的东西不变需求责任、oracle 责任、风险责任——模型和规则同样承担不了

结论

一句话：你的两个新想法方向正确，且是你哲学体系的自然延伸——它们应当被设计为「怀疑者层」，补上「验证已知」与「人类判断」之间的空白。真正有效的不是消灭 review，而是让每一次人类注意力都花在最可能出错的地方——这是「不读代码」执念的唯一正确实现方式。

对 v2 的定位：本设计不推翻 v2 的任何结论；它在 v2 的 Challenge 组件与 Human Gate 组件之间插入一层统计怀疑，并把「设计反刍」从人工闭环升级为「人工 + 机器」双闭环。
