A Verification Methodology · 一门验证方法论

ZK × Graph Engineering 闭环验证
不读一行代码，验证 AI 写的每一行

把 zero-knowledge proof 的协议结构（承诺-挑战-响应-见证）落到 graph engineering 上，形成一条从 meta 到代码的九阶段闭环：项目的世界知识图谱描述业务世界，任务图谱编排开发执行，代码知识图作为两者的物化与校验层。你只读规约与证据，绝不读实现。

方法：ZKP 协议隐喻 × 知识图谱九阶段流水线 × 任务图四规则 产出：世界知识图谱 × 任务图谱 × 代码知识图 工具：code-review-graph MCP 阅读：8 分钟
"Prompt engineers steered the model's words. Loop engineers steered its iterations. Graph engineers steer its topology." — codejunkie99/graph-engineering。本方案把这句再推一步：让验证本身也变成拓扑的一部分——你不读实现，只查验实现投影在图上的指纹。

00 概念校准：为什么是"隐喻"而不是密码学

直觉方向是对的，但 "zero-knowledge proof" 必须严格区分两层含义——整个方案的正确性取决于不混淆它们。

维度密码学 ZKP你真正需要的：免读验证
证明者知道什么一个秘密 witness（如私钥）一份实现（代码）
验证者学到什么零——除了"陈述为真"不学实现细节，但要学结构事实（图、覆盖率、属性通过）
完备性数学保证：验证通过 ⇒ 陈述一定为真概率保证：验证通过 ⇒ 高概率满足规约（存在假阴性空间）
可靠性假证明者几乎不可能骗过取决于测试/属性/图的覆盖强度，不是密码学硬度
落地代价把"代码正确"编码成 NP 电路，任意代码不可行确定性图工具 + 可执行规约，工程可行

结论：你需要的不是密码学 ZKP，而是 ZKP 的协议结构作为一种设计隐喻——落到工程上叫 "规约驱动的免读验证"（Specification-Driven Verification Without Reading Implementation）。ZKP 隐喻里真正可搬的四个组件：

组件一 · Commitment

承诺

AI 写代码前，先把"要实现什么"承诺下来（meta + 规约 + 能力问题），git commit 后不可篡改。

组件二 · Challenge-Response

挑战-响应

验证者（你/CI）向实现发起挑战（测试用例、属性断言、图查询），实现必须答对。

组件三 · Public Verifiability

公开可验证

验证产物（图、测试结果、属性报告）确定性、可复现——任何人重跑都得同样结果，无需信任证明者。

组件四 · Witness Hiding

见证隐藏

实现是 witness，验证者不读它，只检查它对挑战的响应 + 它在图里的结构指纹。

必须诚实标注的硬限制 免读验证抓不住纯语义偏差（逻辑写错了但结构对、签名对、测试恰好没覆盖到）。这是任何免读方法的根本边界，不是本方案的缺陷。因此方案采用分层保证强度：日常循环用概率验证，关键路径加形式化/模型检查，永远保留一个"人类闸门"在不可逆边上——这正是任务图的第④条规则。

01 双图谱总纲：世界知识图谱 × 任务图谱

项目的产出物是两张图；代码知识图是它们的物化与校验层。

Graph Engineering 分两半：知识图谱（智能体记住什么）与任务图（智能体如何工作）。本方案把这两半落成项目的两个一等产出物：

半边一 · 记忆

世界知识图谱 World Knowledge Graph

业务世界是什么样的。节点 = 领域实体（客户、订单、产品、合同），边 = 关系（下单、包含、受约束于），约束 = domain/range 规则，事件 = 业务发生的事（验收→开票）。由阶段 ①-③ 承诺，由阶段 ④ 的代码物化。

半边二 · 工作

任务图谱 Task Graph

开发工作怎么干。节点 = 任务（规划、实现、测试、验证、合并、发布），边 = 执行依赖。遵循任务图四规则：删假边、菱形模式、停止规则、人类闸门。由阶段 ⑤-⑨ 执行，验证代码图是否符合承诺。

交汇层 · 物化

代码知识图 Code Graph

两者的交汇与校验层。世界知识图谱的本体被代码实例化（类型 = 实体，签名 = 关系声明）；任务图谱的每个验证挑战在代码图上执行。它是 witness 的公开投影——你不读代码，只读它的图指纹。

03 逐阶段设计

九个阶段，每个都给出"承诺-挑战-响应-图见证"四件套，并标注"你不读什么"。

①

Meta 承诺：能力问题即本体规格

世界知识图谱

写任何代码前，AI 必须先产出并 git commit meta.yaml：项目领域描述（2 句）+ 10–20 个能力问题（competency questions）+ 实体/关系类型清单。这些问题就是 public statement——项目必须能回答的问题。

承诺物meta.yaml（领域 + 能力问题 + 实体/关系清单），git commit 不可篡改
挑战每个能力问题必须改写为可执行图遍历（如 MATCH (p:Person)-[:CONTRIBUTED_TO]->(s:Service)…）；无法遍历 = 不是图问题 = 打回重定义
响应competency-questions.traversal.yaml——问题 ↔ 遍历模板映射
图见证本体文件自洽性检查（domain/range 实体存在）

你不读什么：不读 meta.yaml 全文——只看自动生成的"能力问题 ↔ 遍历映射表"每条是否映射成功 + 自洽检查报告。

②

Graph Engineering 设计承诺：图规约 Schema

世界知识图谱

承诺物为 ontology.yaml（单一事实源，铁律第 8 条）+ graph-constraints.yaml（domain/range 约束、必须存在的边、禁止的边、模块依赖方向规则）。

承诺物ontology.yaml + graph-constraints.yaml
挑战① 自洽：每个关系 domain/range 实体已定义；② 完备：①的每个能力问题遍历路径上的边类型都在 schema 有声明（无"幽灵边"）；③ 可载入 Protégé 校验
响应schema-validation-report.json（自洽 ✓/✗、完备 ✓/✗、幽灵边清单）
图见证schema 本身

你不读什么：不读 schema 全文——只读 validation report 的 ✓/✗ 和幽灵边清单。

③

架构设计承诺：模块边界 DAG

世界知识图谱

承诺物 architecture-dag.yaml：模块 = 节点，允许的依赖 = 有向边 + 每个模块"职责一句话"。挑战直接采用任务图四规则。

承诺物architecture-dag.yaml
挑战① 无环（拓扑排序）；② 删假边（每条依赖标注"工作真的流过吗"）；③ 菱形可达（可并行模块的依赖不交叉）；④ 人类闸门位置（发布/退款/删除等不可逆边标注 human-gate）
响应architecture-validation.json（环检测、假边清单、并行模块集、闸门位置）
图见证架构 DAG 本身

你不读什么：不读架构设计文档全文——只读校验报告。

④

开发：实现即 Witness

witness 隐藏

这是 ZKP 隐喻的核心：AI 写代码，代码是 witness，你不读任何实现行。代码一写完，code-review-graph 立即确定性抽取——解析器不幻觉、不编造，生成结构指纹。

承诺物代码 + git commit hash（不可篡改）
挑战build_or_update_graph_tool 增量建图（确定性）
响应graph.db（SQLite）+ graph-stats.json（节点/边数、语言、社区）
图见证代码图 = witness 的公开投影，不是 witness 本身——符合"免读实现"

你不读什么：不读任何实现代码——只读它的图指纹（graph-stats + 后续阶段的所有图查询结果）。

⑤

测试设计：挑战集

任务图谱

测试用例 = 挑战集，从阶段 ① 的能力问题机器化而来——"测试用例就是能力问题的机器化"（GE 材料原话）。

承诺物测试用例 = 挑战集
挑战① 每个能力问题 ≥1 个测试（query_graph_tool(pattern="tests_for") 反查）；② 高热度节点（callers 多）必须有测试；③ 属性测试覆盖核心不变量
响应test-coverage-matrix.json（能力问题 × 测试 ✓/✗、高热度无测试节点清单）
图见证覆盖矩阵

你不读什么：不读测试代码——只读矩阵。

⑥

代码质量测试验证：CI 闸门

任务图谱

直接跑，确定性，完全符合 ZKP 的"公开可验证"——任何人重跑 CI 都得同样结果。

承诺物——（CI 无新承诺，执行⑤的挑战集）
挑战编译 / lint / 类型检查通过（编译器 = 一致性检查器）；测试全绿；覆盖率按模块独立设卡
响应ci-report.json（绿/红、覆盖率数字、失败项）
图见证CI 报告

你不读什么：不读代码——只看绿/红 + 数字。

⑦

代码偏差验证：图指纹 vs 规约（关键创新点）

任务图谱

这是整个执念的技术核心：实现是否偏离了规约，不读实现怎么知道？机制：把 ② 的 graph-constraints.yaml 和 ③ 的 architecture-dag.yaml 作为预期图指纹，把 ④ 抽取的实际代码图作为实际图指纹，做图子集/约束校验。

诚实边界 这一步只抓结构性偏差。语义偏差（逻辑写错但结构对）抓不住——那是阶段 ⑧ 的职责。这是免读验证的根本边界。
⑧

业务完备性逻辑验证：可执行规约

任务图谱

业务逻辑用可执行规约表达，而非自然语言：核心流程用状态机建模（订单：created→paid→shipped→delivered，非法转移 = bug）；不变量用属性测试表达（如"订单总额 = ∑ 行项金额"）；关键约束用前置/后置条件（DbC）。

承诺物状态机 + 属性不变量 + DbC 条件
挑战① 状态机模型检查：所有可达状态合法、无死锁、关键状态可达；② 属性测试：随机生成大量输入，不变量恒成立；③ 能力问题回溯：①的每个能力问题用实际图跑遍历，返回非空且语义正确
响应completeness-report.json（状态机 ✓、属性通过率、遍历结果）
图见证完备性报告

你不读什么：不读业务代码——只读状态机验证 + 属性通过率。

诚实标注 这是"完备性"的概率性版本（属性测试是随机的，不证明完备，只证高概率完备）。真正数学完备需要定理证明（Coq/Lean），成本不适合日常循环——列为关键路径可选强验证。
⑨

Meta 与 Graph 的适配性验证：闭环回溯

唯一人类闸门

整个闭环的收口——验证阶段 ① 的承诺（能力问题）在 ④-⑧ 之后是否全部被实际系统兑现。

承诺物阶段 ① 的能力问题清单（你唯一必须读的规约）
挑战① 每个能力问题在实际代码图上执行遍历，结果非空且类型正确；② ⑦ 偏差报告为空；③ ⑧ 完备性报告全绿；④ ⑥ CI 全绿
响应meta-graph-adaptivity.json：能力问题 → 遍历成功 → 结果合法 → 有否偏差，一张总表
图见证适配性总表——全 ✓ = 闭环通过，实现适配 meta 承诺

人类闸门（任务图规则④）：这一步是唯一的人类闸门——你只看一张总表决定是否合并/发布。不读代码，但读"验证证据汇总"。这正好实现你的执念。

04 "你不读代码"的保证机制：证据链而非实现

决策基于证据链，而非实现内容。每一环都确定性、可复现、可机器生成。

proof阶段 ⑤-⑨覆盖矩阵、CI 报告、偏差报告、完备性报告、适配性总表
verifier你只检查 proof 是否全绿，不看 witness
为什么可靠：抽取是确定性的 证据链里的每一条边都来自真实代码——解析器不幻觉、不编造、不猜测。LLM 只出现在最后一层：把图查询结果组织成自然语言。可溯源，因为边就是代码；可验证，因为代码会编译、会测试。这正是知识图谱工程"每条事实带溯源"铁律的免费实现。

06 已知限制与缓解

属性测试是概率性的不证完备，只证高概率完备接受；核心不变量用模型检查/定理证明（关键路径可选）

你唯一必须读的两样东西 ① 阶段 ① 的能力问题清单（规约）——它决定验证什么；② 阶段 ⑨ 的适配性总表（证据）——它告诉你验证结果。这两样不是代码，这正是"不读代码但保证结果"的精确边界。

07 落地路线（PDCA 友好）

四个 Round 渐进建立闭环，每轮独立可交付、可回滚。

Round目标交付验收
1PoC：小项目跑通 ①→⑥meta/ontology/架构承诺 + 建图 + CI + 覆盖矩阵图指纹 + CI 让你不读代码就敢合并小改动
2偏差引擎：加阶段 ⑦预期指纹 vs 实际指纹 diff 规则引擎故意引入一个依赖方向违规，报告能抓到
3可执行规约：加阶段 ⑧状态机 + 属性测试 + DbC故意写错一个业务逻辑（结构对），属性测试能抓到
4适配总表：加阶段 ⑨ + 人类闸门收敛meta-graph-adaptivity.json + 合并/发布流程接入全流程只读证据，不读实现，完成一次发布
  1. 每一轮都验证"验证者本身"：Round 2/3 的验收都包含"故意埋 bug，看报告能否抓到"——测试测试本身（变异思想）。
  2. 每一轮独立可回滚：承诺物与证据都是 git 里的文件，任何一轮不满意可退回到上一轮。
  3. 每一轮结束 git commit：提交历史 1:1 映射循环迭代，便于复查与回退。

08 三句话总结

① 把 ZKP 当协议隐喻而非密码学：承诺规约、隐藏实现、公开证据、验证者只看证据——这就是"不读代码"的结构基础。 —— 概念校准
② 项目产出两张图：世界知识图谱承诺业务世界，任务图谱编排开发执行，代码知识图作为两者的物化与校验层——九阶段闭环就是这两张图的生命周期。 —— 双图谱总纲
③ 你唯一必须读的是能力问题（规约）与适配性总表（证据）；偏差报告、属性验证与人类闸门共同兜住免读验证的根本边界。 —— 保证与边界
