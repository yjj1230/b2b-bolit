准确性说明与实现边界

  1. “可读可写/只读不可改”是页面或 API 的有效字段权限，不是数据库账号权限。业务身份不能直接连接数据库；后端先通过 SpiceDB/ReBAC 判断资源级权限，再由 BFF 做字段裁剪。
  2. 数据库表与字段已做全量比对。数据库 HTML 与五个迁移 SQL 均为 29 张表、254 个物理字段，表名及字段名一致；其中运行期业务/支撑表按节点分布到流程矩阵，且每次展示均包含该表全部物理字段。legacy_flow_mapping、migration_batches 只服务历史迁移批次，不属于这 16 个日常业务节点，因此未硬塞入流程矩阵。
  3. 仓管与客户联系人剥离价格和内部备注已有代码及测试依据。ProjectOrder/ProjectShipment 对 WAREHOUSE/CONTACT 移除 unit_price_cents、amount_cents 与内部备注。
  4. “业务动作写入”不等于直接修改列。审批、确认发货、放行等动作由服务在事务内写入状态、处理人、事件链和 outbox；底层状态字段对人工仍不可直接编辑。
  5. 事件链与凭证版本不可原地修改。order_events 等五类事件表是 append-only；evidence_versions 只追加版本，不提供 UPDATE/DELETE 路径。
  6. 数据库缺口已经与物理字段彻底分离。orders.payload 与 pre_orders.candidates 仍按真实 JSONB 物理列出现在矩阵；其子路径、派生金额、物流轨迹、发票凭证与 OCR 结构化结果只出现在各场景末尾的独立缺口清单，不再作为数据库字段混排。
  7. 原型按钮不自动证明后端已实现。“写备注”、智能候选修改、商务全量筛选等若只出现在原型文案中，本文保留场景预期，但明确放入缺口清单，供后续开发核对。
